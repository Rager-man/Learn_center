# 数据结构开发五级学习路线

> 目标：从数据结构完全新手到能独立做项目——会手写、会选型、会落地。业余时间约 4–6 个月。
> 前置要求：TypeScript 基础（函数、class、泛型初步，对应 TypeScript 课程等级 1–2）；vitest 基本用法会在等级 1 用到，没有也不怕，边用边补。
> 与 TypeScript 课程的关系：所有结构都用 TS 手写实现——正好用上那边的泛型与 vitest，两门课互相巩固。
> 用法：每完成一项练习或达标一项标准，把 `[ ]` 改成 `[x]`。所有晋级标准打勾后，再进入下一等级。

## 等级 1：线性结构与复杂度分析——先学会数代价（约 2–3 周）

**核心认知：数据结构 = 组织数据的方式，它决定了每个操作的代价。学结构之前先学会"数代价"（复杂度分析），否则永远只能背结论。**

### 需要掌握
- Big-O 表示法：O(1)、O(log n)、O(n)、O(n log n)、O(n²)；最好 / 最坏 / 平均情况的区别
- 数组 vs 链表的内存模型：连续存储 vs 节点分散 + 指针连接；为什么数组对 CPU 缓存更友好
- 动态数组：容量与长度的区别、倍增扩容、为什么均摊（amortized）下来 push 是 O(1)
- 单链表 / 双链表：头尾插删、按值查找、反转、快慢指针找中点、判环
- 栈（LIFO）与队列（FIFO）：各用数组、链表两种底层实现一遍
- 用 TS 泛型定义结构接口：`class Stack<T>`——接口先行，实现后行

### 常见错误
- 循环边界 off-by-one：`<` 与 `<=` 分不清；链表遍历用 `while (cur.next)` 还是 `while (cur)` 想当然
- 链表删除时先断线再接线，后续节点的引用直接丢了——正确顺序永远是先接新的、再断旧的
- 不知道 JS 数组的 `shift` / `unshift` / `splice(0, n)` 是 O(n)，在循环里当 O(1) 用
- 动态数组扩容逻辑错：忘了扩容后更新容量、扩容时机与倍数随意定、缩容条件没想过
- 反转链表迭代版写完，忘了把 head 指向新的头节点
- 用数组模拟队列从头部 `shift` 出队——每出队一个元素，全体搬一次家

- [ ] ex2 手写 `DynamicArray<T>`：push / pop / get / insert / remove / resize，每个方法注释标复杂度
- [ ] ex3 手写 `SinglyLinkedList<T>` 与 `DoublyLinkedList<T>`：插删查、反转、找中点、判环（快慢指针）
- [ ] ex4 手写 `Stack<T>` 与 `Queue<T>`：各用"数组底层"和"链表底层"实现两遍，对外接口保持一致
- [ ] ex5 经典题实战：有效括号匹配（栈）；选做：滑动窗口最大值（双端队列）
- [ ] 每个结构配 vitest 测试——直接复用 TypeScript 课的测试技能

## 等级 2：递归、树与堆——学会拆解问题（约 3–4 周）

**核心认知：树是递归定义的结构，掌握树 = 掌握"把大问题拆成同构子问题"的思维；堆则是"用数组隐式表示一棵树"的第一个巧妙设计。**

### 需要掌握
- 递归三要素：base case（何时停）、子问题（怎么缩小）、组合（子问题的答案怎么拼成原问题的答案）；递归与调用栈的关系、为什么会栈溢出
- 二叉树：前序 / 中序 / 后序遍历（递归 + 迭代各写一遍）、层序遍历（队列）
- 二叉搜索树（BST）：插入、查找、删除——重点啃下"删除有两个子节点的节点"（找后继）
- BST 核心性质：中序遍历结果有序——校验 BST 全靠它
- 堆：用数组实现（父子下标公式）、siftUp / siftDown、heapify 建堆、优先队列
- Trie 前缀树：insert / search / startsWith，自动补全的底层原理
- 埋个伏笔：往 BST 按序插入会退化成链表——记住这个痛点，等级 4 的平衡树就是来解决它的

### 常见错误
- 递归缺 base case，或 base case 覆盖不全：只判了 `root === null`，没想到叶子节点的子树也要判
- BST 删除只处理了 0 个和 1 个子节点的情况，两个子节点的情况漏了
- 堆的下标公式算错：0 起始的数组里 i 的孩子是 2i+1 和 2i+2，背成 2i 和 2i+1
- 建堆从最后一个元素开始 siftDown——应该从最后一个**非叶子**节点开始
- 迭代版前序遍历：要先推右孩子再推左孩子（栈是反的），写成先左后右输出顺序就反了
- 递归题不先想三要素就动手，写到哪里算哪里，返回值一层层传错

- [ ] ex7 `BST<T>` 完整增删查 + 中序遍历验证有序 + 随机插删压力测试
- [ ] ex8 手写 `ArrayHeap<T>`：siftUp / siftDown / heapify，外包一层优先队列接口
- [ ] ex9 Top-K 问题：流式数据只过一遍就取出最大的 K 个数（小顶堆的妙用）
- [ ] ex10 手写 `Trie` + 命令行自动补全小工具

## 等级 3：哈希表与图——工程里出镜率最高的结构（约 3–4 周）

**核心认知：哈希用"计算"换"索引"，把查找打到 O(1)；图用"关系"建模世界——依赖、路径、网络全是图。这两样是工程中使用频率最高的结构。**

### 需要掌握
- 哈希函数的职责、冲突处理：链地址法 vs 开放寻址
- 负载因子（load factor）、扩容与全量 rehash；JS 的 `Map` / `Set` 底层就是哈希
- 图的表示：邻接表 vs 邻接矩阵怎么选；有向 / 无向、加权 / 无权
- BFS / DFS（迭代版为主，配显式的队列和栈）、连通分量
- 拓扑排序（Kahn 算法）：依赖关系的正确执行顺序 + 环检测
- 并查集（Union-Find）：路径压缩 + 按秩合并，均摊接近 O(1)
- Dijkstra 最短路径：优先队列驱动（直接复用等级 2 的堆）；负权边为什么让它失效（概念即可）

### 常见错误
- 图遍历忘记标记 visited，有环直接死循环——BFS 和 DFS 都会踩
- 哈希扩容后忘记把旧桶数据全量 rehash 进新桶，老数据"消失"了
- 邻接表存无向图忘记加双向边，遍历结果残缺
- 并查集的 find 不做路径压缩，链一长退化成 O(n) 还不自知
- Dijkstra 每轮用数组线性扫最小值，写成了 O(n²) 还以为是自己哪里写错了
- 拓扑排序的入度表初始化漏统计、出队后漏减邻居入度——队列提前空 / 输出数量对不上

### 练习（代码放 `03_哈希与图/`）
- [ ] ex11 手写 `HashTable<K, V>`：链地址法 + 负载因子超限自动扩容 rehash；和原生 Map 对比 10 万条数据的性能
- [ ] ex12 哈希经典题：两数之和——先写暴力 O(n²) 再写哈希 O(n)，亲手量出差距
- [ ] ex13 图的邻接表实现 + 迭代版 BFS / DFS
- [ ] ex14 课程表问题：拓扑排序判断能否修完所有课（含环检测）
- [ ] ex15 手写并查集 + 岛屿数量 / 朋友圈问题
- [ ] ex16 Dijkstra 加权最短路（用等级 2 的堆）
- [ ] mini 项目：地铁线路查询工具——建图 + 最短路 + 命令行交互

## 等级 4：平衡、组合与工程化——从会写到会用对（约 1–2 月）

**核心认知：工业级结构 = 基础结构的组合与权衡（LRU = 哈希表 + 双向链表）；真实工程的选型原则是"够用且简单"优先——数据结构不是越高级越好。**

### 需要掌握
- AVL 树：四种失衡情况（LL / RR / LR / RL）与旋转，插入的自平衡实现
- 红黑树（概念级）：为什么工业界（数据库索引、Linux 内核）选它而不是更"平衡"的 AVL
- B 树 / B+ 树（概念级）：数据库索引为什么用它——磁盘 IO 与扇出的关系
- 跳表（skip list）：插入 / 查找 / 删除的实现；Redis 的有序集合为什么选跳表不选树
- 组合结构设计：LRU Cache = 哈希表 + 双向链表，get / put 都是 O(1)
- 抽象数据类型（ADT）与 API 设计：不变量（invariant）——结构内部永远成立的性质，靠它证明实现正确
- 随机测试思维：随机操作序列 + 每步后校验不变量，比手写用例更能抓住结构性 bug
- 基准测量：`performance.now()` 计时、预热、多轮取中位数，避开常见测量陷阱

### 常见错误
- 过度设计：数据量一百条，数组遍历绰绰有余，非要上树 / 图——先简单，再正确，后优化
- AVL 四种旋转情况判断混：先判失衡方向、再判子节点方向，两步走，不要想着一步到位
- 跳表随机层数没限制最高层，或删除时忘了逐层摘除节点
- LRU 双向同步漏一边：链表删了节点、哈希表没删 key（或反之），容量慢慢错位
- 基准测试冷启动直接开测、只测一轮、拿不同规模的数据比大小
- 库的 API 不一致：有的方法返回节点、有的返回值、有的返回 boolean——用的人每处都得查

### 练习（代码放 `04_平衡与工程化/`）
- [ ] ex17 手写 AVL 树（插入 + 旋转 + 查找）：随机顺序插入 1000 个数，验证树高受控、中序有序
- [ ] ex18 手写跳表，和普通 BST 对比"按序插入"场景下的查找性能，写出结论
- [ ] ex19 手写 LRU Cache（哈希 + 双链表），万级随机操作压力测试
- [ ] ex20 把等级 1–3 的结构整理成 mini 库：统一接口风格 + README（每个结构标复杂度表）+ 共享测试模式
- [ ] ex21 性能实验报告：数组 vs 链表 vs 跳表在不同规模下的查找耗时，列表格下结论
- [ ] ex22（选做）红黑树概念笔记：用自己的话 + 图示讲清插入时的着色与旋转

### 晋级标准
- [ ] AVL 任意顺序插入 1000 个数，树高在 O(log n) 内、中序始终有序
- [ ] LRU 通过压力测试，且能讲清为什么 get / put 每一步是 O(1)

## 等级 5：独立项目——用结构解决真实问题（约 1–2 月）

**独立做项目 = 在真实约束（需求、性能、可维护性）下做结构选型并落地。会写 20 种结构，不如会在对的场景用对 1 种。**

### 需要掌握（做中学）
- 选型方法论：先给需求画"数据操作画像"——读写比？要顺序还是要随机访问？要范围查询吗？数据量级多大？——再对着画像选结构
- 项目级工程：模块拆分、错误处理、数据持久化（结构怎么序列化 / 反序列化）
- 性能剖析：先测量、再优化；完整记录一次"发现问题 → 定位 → 优化 → 复测"的过程
- 核心结构非平凡的候选项目，四选一（或自定义等价项目）：
  - 内存 KV 存储（mini Redis）：哈希表 + 跳表有序集合 + LRU 淘汰 + TTL 过期，命令行协议交互
  - 文本编辑器内核：gap buffer（或行链表）+ undo/redo 栈 + 剪贴板队列，支持光标移动与增删
  - 任务调度器：优先队列 + 依赖拓扑排序 + 到期触发，命令行可观测运行
  - 路径规划工具：图建模真实地铁 / 校园路网 + Dijkstra（A* 初见），交互查询

### 常见错误
- 拿着锤子找钉子：学了跳表恨不得哪里都用——选型要从操作画像出发，不是从"我想用它"出发
- 不测量就优化：凭感觉换结构，换完到底快没快、快多少，说不出来
- 只在内存里玩：结构没有序列化 / 反序列化，一重启全丢——离"能用"还差一步
- 核心结构直接 import 第三方库——这门课的毕业项目要求核心结构全部自实现
- 只交付代码不交付文档：别人（包括三个月后的自己）不知道怎么跑、为什么这么设计

### 练习（毕业项目，代码放 `05_毕业项目/`，选一个完整交付）
- [ ] 选型文档：数据操作画像、最终选择、被否掉的候选及理由
- [ ] 核心结构全部自实现（不引第三方），带测试与复杂度注释
- [ ] 基准数据：与朴素实现（比如全用数组）对比 + 至少一次真实调优记录
- [ ] 有持久化或交互能力——不是纯算法题解，是个"能用的东西"
- [ ] README 完整：别人 `npx tsx` 就能一键跑起来
- [ ] 答辩自测：能向别人讲清每个结构为什么选它、瓶颈在哪、还能怎么优化

### 毕业标准（"能独立做项目"的定义）
- [ ] 给一个新需求，能独立走完"操作画像 → 候选结构 → 取舍 → 落地"全流程
- [ ] 性能问题能自己定位：测量、剖析、复测，不靠猜
- [ ] 选型说得出理由：为什么用它、不用它会怎样、数据量涨 100 倍会怎样
- [ ] 有至少 1 个完整交付物：别人照着 README 能跑起来

## 路线设计说明

- 顺序按依赖关系编排：等级 2 的堆直接服务等级 3 的 Dijkstra，等级 1 的双链表 + 等级 3 的哈希组合成等级 4 的 LRU，等级 4 的一切汇入等级 5 的项目——学到后面等于复习前面
- 红黑树、B+ 树只到概念级：目标是"看得懂别人为什么这么设计"，手写它们的投入产出比太低；AVL 和跳表才值得亲手写
- 为什么用 TS：JS 原生结构少（没有原生堆 / 树 / 图），正好逼你全部手补；泛型与 vitest 直接衔接 TypeScript 课程，两门课互相巩固
- 每级穿插经典题（括号匹配、两数之和、Top-K）：不是为了刷题，是让手写的结构立刻有"被使用"的场景，防止学完就忘
- 明确不覆盖：动态规划、字符串算法（KMP 等）、网络流——这些属于"算法"课范畴，本路线走完可以另开一门
- 每一级的晋级标准都是"能做到什么"，不是"看过什么"——卡在某一级，比带着窟窿往前走快
