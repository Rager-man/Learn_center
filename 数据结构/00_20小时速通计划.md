> 目标：用 10 次 × 2 小时，掌握数据结构最重要的 20%——每个结构**亲手用 TS 写一遍、配上测试、标上复杂度**，最后组合出一个带 LRU 淘汰和 TTL 过期的 mini KV 缓存。
> 前置要求：TypeScript 课第 1–7 次（strict、泛型）；第 8 次的 vitest 三板斧（`describe` / `it` / `expect`，三个词够用）最好先过，没过也不怕——第 1 次的第一个结构带照抄示例，边用边补。

## 怎么用这份计划

- **每次的节奏**：约 30 分钟学（读学前阅读）→ 80 分钟练（写代码）→ 10 分钟复盘。
- **复盘的正确姿势**：合上代码，先凭记忆把复盘问题的答案**口述或写下来**，再打开验证。"感觉我知道"不算数——能说出来才是真的会。
- **建议隔天一次**，3–4 周完成。间隔重复比连续突击记得牢得多。
- **卡住超过 20 分钟**就求助：把你期望什么、实际发生什么、完整报错贴给 AI 导师（也就是我），别自己耗着。
- 练习做不完就压缩范围，**但复盘不能跳过**。
- 完成一项练习就把 `[ ]` 勾成 `[x]`。
- 三条底线贯穿全程：
  1. **每个结构 vitest 全绿才准进下一课**——带着红测试往前走，窟窿只会越来越大；
  2. **每个方法注释标复杂度**——"会数代价"是这门课的元技能，标不出来的方法等于没写懂；
  3. strict 下 0 error、不写 any、`npx tsx` 直跑（TS 课的纪律原样继承）。

## 最重要的 20% 是什么

数据结构的世界深不见底——平衡树、跳表、B+ 树、线段树……但日常工程和面试里真正天天用的就那么几样。以下 9 项就是那关键的 20%：

| #   | 核心内容                    | 为什么重要                                          |
| --- | ------------------------- | ------------------------------------------------- |
| 1   | 复杂度分析（Big-O）            | 元技能。不会数代价，所有结构只能背结论；会数代价，新结构看一眼就懂     |
| 2   | 动态数组 + 均摊分析              | 日常用得最多的结构；"push 均摊 O(1)"是第一个非平凡的分析      |
| 3   | 链表与指针操作                  | 节点 + 引用的思维地基，是后面一切树结构的直通车道             |
| 4   | 栈与队列                     | 最简单的结构却无处不在：括号匹配、撤销栈、BFS 的引擎           |
| 5   | 递归 + 二叉树遍历               | "把大问题拆成同构子问题"的思维训练场，递归三要素想清，树题变填空题 |
| 6   | BST + 堆（优先队列）            | "有序数据"的两个答案：查找用 BST，取最值用堆；Top-K / 调度的底层 |
| 7   | 哈希表                       | 工程出镜率之王；理解冲突与扩容，才知道 Map / Set 为什么快、什么时候慢 |
| 8   | 图 + BFS / DFS             | 关系建模的世界——依赖、路径、网络全是图；两个遍历是万能钥匙     |
| 9   | 组合设计（LRU Cache）          | 工业级结构不是发明的是组合的；这一课从"会写结构"跨到"会设计结构"   |

### 明确砍掉的 80%（20 小时内不碰）

- **AVL / 红黑树 / B+ 树的手写**：投入产出比太低，概念级即可——一句话结论先拿着：数据库索引用 B+ 树是因为磁盘按块读、扇出大树就矮（长期路线等级 4）
- **跳表**：Redis 有序集合的底层，值得学，但不在关键 20% 里（等级 4）
- **Trie 前缀树**（路线图 ex10）：自动补全的底层，后补不迟（等级 2 尾巴）
- **并查集、Dijkstra**（ex15、ex16）：算法味浓于结构味；且都以你这次会掌握的堆和图为基础，之后捡起来极快（等级 3 尾巴）
- **基准测量方法论、mini 库工程化**（ex20、ex21）：测量科学是"结构写对了"之后的事（等级 4）
- **动态规划、KMP、网络流**：属于"算法"课范畴，路线图也明确不覆盖——本课的近亲只有复杂度分析

这些不是不学，是现在不学——长期路线图（[00_学习路线图.md](00_学习路线图.md)）里都有安排。

## 10 次课

### 第 1 次 · 数代价 + 动态数组——一切的地基

> **核心认知：数据结构 = 组织数据的方式，它决定每个操作的代价。学结构之前先学会"数代价"（Big-O），否则永远只能背结论。**

- 代码放：`01_线性结构/`（上课时创建）
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)（免费中文书，代码带 TS 版）的「复杂度分析」章 + 「数组与链表」章的数组部分；英文吃力就让 AI 导师 10 分钟讲一遍

**学习目标**
- 会读会标 Big-O：O(1)、O(log n)、O(n)、O(n log n)、O(n²)；分清最好 / 最坏 / 平均情况
- 从内存模型讲清数组：连续存储 → 随机访问 O(1)、中间插删 O(n)；知道 JS 数组的 `shift` / `unshift` / `splice` 是 O(n)
- 区分容量（capacity）与长度（length）；理解倍增扩容与**均摊（amortized）**：为什么 push 平均下来是 O(1)

**练习任务（80 分钟）**
- [ ] （20 分钟）ex1 复杂度标注：写（或让 AI 导师出）6 段带循环嵌套的代码，逐段标 Big-O 并写一句理由——重点抓"循环次数由什么决定"
- [ ] （60 分钟）ex2 手写 `DynamicArray<T>`：push / pop / get / insert / remove / resize，每个方法注释标复杂度；写完配 vitest（含扩容触发、越界报错）；第 1 个测试照抄 TypeScript 课第 8 次的写法起步

**复盘问题**
1. 数组随机访问为什么是 O(1)？连续内存在这里帮了什么忙？
2. push 的"均摊 O(1)"是怎么算出来的？最坏的那一次发生了什么？
3. JS 数组有哪些方法是隐藏的 O(n)？在循环里用它们的后果是什么？

### 第 2 次 · 链表——用指针换灵活

> **核心认知：链表用"指针"换"灵活"——插删 O(1)，但查找 O(n)。节点 + 引用的思维一旦建立，后面的树就是"会分叉的链表"。**

- 代码放：`01_线性结构/`
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「数组与链表」章的链表部分——重点看内存图示，图看懂了一半就懂了

**学习目标**
- 单链表 / 双链表的结构；头尾插删、按值查找，每步标复杂度
- 指针操作铁律：**先接新的、再断旧的**——顺序反了，后续节点直接丢
- 快慢指针两板斧：找中点、判环

**练习任务（80 分钟）**
- [ ] （35 分钟）ex3a 手写 `SinglyLinkedList<T>`：头尾插、按值删、按值查、toArray；删除操作先在纸上画箭头再动手
- [ ] （25 分钟）ex3b 反转链表（迭代版，写完把 head 指向新头）+ 快慢指针：找中点、判环——各配测试
- [ ] （20 分钟）ex3c 手写 `DoublyLinkedList<T>`：头尾插删——不用做全功能，够用就行，它第 9 次要在 LRU 里当主角（伏笔正式埋下）

**复盘问题**
1. 链表删除为什么必须"先接新、再断旧"？顺序反了具体会发生什么？
2. 数组 vs 链表：查找、头部插入、尾部追加各自的代价是什么？根因分别在哪？
3. 快慢指针判环为什么不会跳过？无环时 fast 在哪一步停下来？

### 第 3 次 · 栈与队列——限制换来纪律

> **核心认知：栈和队列不是新结构，是"限制访问位置"的线性结构。限制听起来是坏事，换来的是严格的顺序纪律（LIFO / FIFO）——撤销栈、括号匹配、BFS 全靠它。**

- 代码放：`01_线性结构/`
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「栈与队列」章

**学习目标**
- `Stack<T>`（push / pop / peek）与 `Queue<T>`（enqueue / dequeue），操作全部 O(1)
- 同一接口、两种底层（数组 / 链表）各实现一遍——体会"接口与实现分离"
- 知道数组队列裸用 `shift` 出队是 O(n) 的灾难，循环数组怎么解决（概念）

**练习任务（80 分钟）**
- [ ] （50 分钟）ex4 手写 `Stack<T>` 与 `Queue<T>`：各用"数组底层"和"链表底层"实现两遍，对外接口保持一致，同一套测试两种实现都要过
- [ ] （30 分钟）ex5 经典题实战：有效括号匹配（栈）；再用两个栈实现一个队列——体会"结构模拟结构"，均摊代价是多少？

**复盘问题**
1. 为什么数组队列裸用 `shift` 是灾难？循环数组的思路是什么？
2. 括号匹配为什么天然适合栈？"最近的相关性"在这里指什么？
3. 两个栈怎么模拟一个队列？出队的均摊代价为什么是 O(1)？

### 第 4 次 · 递归与二叉树——学会拆解问题

> **核心认知：树是递归定义的结构——每棵子树都是更小的同类问题。递归三要素（base case / 子问题 / 组合）想清楚，树题就变成了填空题。**

- 代码放：`02_树与堆/`（上课时创建）
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「树」章的前半（结构定义与遍历）；递归生疏就先把三要素让 AI 导师讲一遍

**学习目标**
- 递归三要素：base case（何时停）、子问题（怎么缩小）、组合（子答案怎么拼成原答案）；递归与调用栈的关系、为什么会栈溢出
- 前序 / 中序 / 后序遍历：递归版 + 迭代版各写一遍——迭代版必须能解释栈里每一步
- 层序遍历用队列（第 3 次的 `Queue<T>` 直接复用——第一次体验"结构被使用"）

**练习任务（80 分钟）**
- [ ] （50 分钟）ex6 二叉树三种遍历的递归版 + 迭代版，外加层序遍历；迭代前序注意：栈是反的，**先推右、再推左**
- [ ] （30 分钟）递归思维题：最大深度、翻转二叉树——每题先把三要素**口述出来**再写代码

**复盘问题**
1. 递归三要素是什么？"最大深度"这题的三要素分别是什么？
2. 迭代版前序遍历为什么先推右孩子？中序迭代版的走到最左是什么操作？
3. 层序遍历为什么必须用队列？换成栈会发生什么？

### 第 5 次 · 二叉搜索树——有序数据的第一个答案

> **核心认知：BST 用"左小右大"这个不变量把查找压到 O(h)。中序遍历有序是它的身份证，删除双子节点是它的成人礼。**

- 代码放：`02_树与堆/`
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「树」章的二叉搜索树一节

**学习目标**
- insert / search / 中序遍历；删除的三种情况——重点啃**双子节点找后继**
- 不变量（invariant）思维："中序有序"就是一道测试，能证明整棵树实现正确
- 亲眼看到退化：按序插入 1、2、3…，树变成链表——记住这个痛点，平衡树（砍掉的那 80%）就是来解决它的

**练习任务（80 分钟）**
- [ ] （60 分钟）ex7 手写 `BST<T>`：完整增删查 + vitest；删除必须覆盖三种情况，每种都有测试
- [ ] （20 分钟）随机插删压力测试：随机插 1000 个数，边删边插，每步后中序校验有序；再按序插入 1000 个数，对比树高——把两个数字写进注释

**复盘问题**
1. BST 删除双子节点的标准操作是什么？为什么是找后继而不是前驱（或随便一个叶子）？
2. 只用一道测试证明 BST 实现正确，你选哪道？它为什么够（不变量思维）？
3. 什么操作序列让 BST 退化成链表？退化后查找变成多少？谁后来救了它？

### 第 6 次 · 堆与优先队列——藏在数组里的树

> **核心认知：堆 = 用数组隐式表示一棵完全二叉树——没有指针，树靠下标公式存在。它是 Top-K 和任务调度的引擎。**

- 代码放：`02_树与堆/`
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「堆」章

**学习目标**
- 0 起始数组的父子下标公式：i 的孩子是 2i+1 / 2i+2，父是 (i-1)>>1——背错一个全盘崩
- siftUp / siftDown / heapify 建堆；概念上说得清 heapify 为什么是 O(n)
- Top-K 的反直觉套路：取**最大**的 K 个用**小顶**堆——堆顶永远是"K 个里最该被淘汰的"

**练习任务（80 分钟）**
- [ ] （50 分钟）ex8 手写 `ArrayHeap<T>`（小顶堆）：siftUp / siftDown / push / pop / heapify，外包一层 `PriorityQueue<T>` 接口；配测试
- [ ] （30 分钟）ex9 Top-K：10 万个随机数**只过一遍**，取出最大的 50 个；对比"全排序再切片"的耗时——数据量不用真跑 10 万，1 万够看到差距

**复盘问题**
1. i 的父子下标公式是什么？为什么不用指针就能表示一棵树？
2. heapify 建堆为什么是 O(n) 而不是 O(n log n)？（概念说得清即可）
3. 取最大的 K 个为什么用小顶堆？堆顶那个元素在"演"什么角色？

### 第 7 次 · 哈希表——用计算换索引

> **核心认知：哈希用"计算"换"索引"，把查找打到 O(1)。理解冲突处理与扩容 rehash，才知道 Map / Set 为什么快、什么时候会突然慢一下。**

- 代码放：`03_哈希与图/`（上课时创建）
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「哈希表」章

**学习目标**
- 哈希函数的职责、链地址法处理冲突；负载因子（load factor）超限 → 扩容 → **全量 rehash**
- 理解 JS 的 `Map` / `Set` 底层就是哈希——手写一遍后再用它们，你知道每次 `.get()` 背后发生了什么
- 哈希题的通用套路：用空间换时间

**练习任务（80 分钟）**
- [ ] （55 分钟）ex11 手写 `HashTable<K, V>`：链地址法 + 负载因子超 0.75 自动扩容 rehash；测试：连续插 1 万条全部可查，删一半再插 1 万条依然全对
- [ ] （25 分钟）ex12 两数之和：先写暴力 O(n²) 再写哈希 O(n)，1 万条数据各计时——亲手量出一个数量级的差距

**复盘问题**
1. 负载因子是什么？超限后发生什么？为什么必须全量 rehash、不能只搬一部分？
2. 两数之和从 O(n²) 到 O(n)，省下来的时间是用什么换的？
3. 哈希查找"永远 O(1)"吗？列出至少两种它变慢的情形。

### 第 8 次 · 图与 BFS / DFS——关系建模的世界

> **核心认知：图 = 节点 + 边。一旦把问题翻译成图（依赖、路径、网络），BFS 和 DFS 就是万能钥匙——两者的区别只是用队列还是用栈。**

- 代码放：`03_哈希与图/`
- 学前阅读（约 30 分钟）：[Hello 算法](https://www.hello-algo.com)「图」章；遍历部分注意与第 4 次树遍历的对照——图多了个 visited

**学习目标**
- 邻接表表示法；有向 / 无向（无向图加双向边）；为什么不用邻接矩阵（稀疏图空间爆炸）
- visited 标记防死循环——有环的图不标记，BFS 和 DFS 都会原地转圈
- 拓扑排序（Kahn 算法）：入度表 + 队列，输出依赖的正确执行顺序，顺便检测环

**练习任务（80 分钟）**
- [ ] （40 分钟）ex13 邻接表 `Graph` + 迭代版 BFS / DFS（显式用第 3 次的队列和栈）+ 连通分量计数
- [ ] （40 分钟）ex14 课程表问题：给先修依赖判断能否修完所有课（拓扑排序判环）；能修完就输出一个合法修课顺序

**复盘问题**
1. 忘记 visited 会发生什么？自环、互相引用这两种情况分别怎么炸？
2. Kahn 拓扑排序的完整流程？"输出数量 < 总节点数"为什么说明有环？
3. BFS 和 DFS 各适合什么问题？最短路为什么是 BFS 的主场（无权图）？

### 第 9 次 · 组合设计——LRU Cache

> **核心认知：工业级结构不是发明出来的，是组合出来的。LRU = 哈希表（O(1) 定位）+ 双向链表（O(1) 摘接）——每个组件只做自己最擅长的事。**

- 代码放：`04_平衡与工程化/`（上课时创建）
- 学前阅读：无新材料——把第 2 次的双链表和第 7 次的哈希表代码重读一遍，这本身就是最好的复习

**学习目标**
- 组合设计思维：先问"这个操作需要什么能力"，再问"哪个结构提供这个能力"，最后"怎么把两者缝起来"
- get / put 全 O(1) 的达成路径：哈希定位节点，链表摘接调序
- 双向同步纪律：链表动了、哈希必须跟着动——漏一边，容量慢慢错位

**练习任务（80 分钟）**
- [ ] （60 分钟）ex19 手写 `LRUCache<K, V>`：**复用/改造**第 2 次的 `DoublyLinkedList` 和第 7 次的 `HashTable`（或直接用原生 `Map` 承担哈希职责，理由写进注释）；容量满淘汰最久未用；get 命中要"提到最新"
- [ ] （20 分钟）万级随机操作压力测试（容量 100，随机 get / put 一万次，随时抽查"最久未用的到底是不是它"）；再和朴素实现（数组线性扫）计时对比

**复盘问题**
1. LRU 里哈希表和双向链表各自负责什么能力？砍掉一个会失去什么？
2. get 命中时要维持什么不变量？哪几步操作必须"两边一起动"？
3. 什么使用场景下 LRU 是错误选择？（提示：偶尔来一次的全量扫描）
