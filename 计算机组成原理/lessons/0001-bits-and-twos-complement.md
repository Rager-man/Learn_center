## §1 核心认知：计算机里没有"数"，只有位

> ◆ **本课唯一必须带走的东西**
>
> **同一个位串，在不同编码约定下是不同的值。补码不是"表示负数的技巧"，是一条模运算恒等式——它让一套加法器顺便会算了减法。**

眼见为实。一个字节，8 位全 1，写作 `1111 1111`（十六进制 `0xFF`）：

| 编码语境                    | 它的值                          |
| --------------------------- | ------------------------------- |
| 无符号字节（uint8）          | 255                             |
| 有符号字节（int8，补码约定） | −1                              |
| JS 数值字面量 `0xFF`        | 255——但它是个 double，下一课主角 |

位一个都没变。变的是**你怎么读它**。这就是本课程第二条底线"说清编码语境"的出处：写下任何一个位串，都要能说出它在什么语境下是什么值——以后你看类型转换的怪现象、排查溢出 bug，第一反应应该是"位串是什么、语境换了没有"，而不是"这语言有毛病"。

三个推论，每个都值回今天的学费：

1. **类型转换的坑，根子都在"语境换了，认知没跟上"。**把 int8 的 `1111 1111` 塞进 uint8，位没变，值从 −1 跳到 255——转换改写的是"解读方式"，不是位本身。
2. **溢出不会报错，它只是丢位。**位宽是物理事实（8 根线就是 8 根线），算出来的第 9 位没地方放，会被丢掉，剩下的位被按原语境重新解读——`127 + 1 = −128` 不是算错，是丢位后的正确解读。
3. **CPU 里没有减法器。**`a − b` 就是 `a + (256 − b)` 再丢掉第 9 位（8 位语境）。加法器一套电路通吃加减——这是数学（模运算）替硬件省的钱，不是工程师的魔法。

> ⚠️ **本课避坑**
> 别把"取反加一"当口诀背。口诀会在两个地方背叛你：一是别人问"补码的补码是什么、为什么"，二是遇到 −128 这种边界。今天的 §2.2 会把口诀还原成一条恒等式——从那条恒等式出发，所有口诀你自己就能推出来。

## §2 看清你写下的东西（30 分钟）

学前阅读讲"补码是什么"。这一节讲四件教材不会直说的事：进制转换的手感、补码的模运算本质、溢出与进位的分工、以及 JS 位运算把你悄悄换到哪个语境。

### §2.1 进制转换：两个方向，四套动作

**整数 → 二进制：除 2 取余，倒排。**以 45 为例：

```text
45 ÷ 2 = 22 …… 1   ← 最低位
22 ÷ 2 = 11 …… 0
11 ÷ 2 =  5 …… 1
 5 ÷ 2 =  2 …… 1
 2 ÷ 2 =  1 …… 0
 1 ÷ 2 =  0 …… 1   ← 最高位
```

从下往上读：`101101`。验算：32 + 8 + 4 + 1 = 45 ✓。

**小数 → 二进制：乘 2 取整，正排。**以 0.6875 为例：

```text
0.6875 × 2 = 1.375   → 取 1，剩 0.375
0.375  × 2 = 0.75    → 取 0，剩 0.75
0.75   × 2 = 1.5     → 取 1，剩 0.5
0.5    × 2 = 1.0     → 取 1，剩 0 —— 停！
```

从上往下读：`0.1011`。验算：0.5 + 0.125 + 0.0625 = 0.6875 ✓。

**反向：按权展开。**`1011.1011`：整数部分 8+2+1 = 11，小数部分 0.5+0.125+0.0625 = 0.6875，合计 **11.6875**。小数点左边权是 1, 2, 4, 8…，右边是 0.5, 0.25, 0.125…——一套权重，小数点是个记号。

**二 ↔ 十六：4 位一组。**`101101` 补齐成 `0010 1101`，每组读成一位十六进制：`2` 和 `D` → `0x2D`。十六进制存在的意义就是二进制的"速记"——每 4 位二进制恰好对应 1 位十六进制，不多不少。

> ⚠️ **0.1 的真相（下一课整集的伏笔）**
> 拿 0.1 走一遍乘 2 取整：0.1→0.2→0.4→0.8→1.6→1.2→0.4——0.4 回来了，从此 `0011` 无限循环：`0.1 = 0.0001100110011…₂`。原因一句话：十进制 0.1 = 1/10，分母含素因子 5；而有限二进制小数的分母只能是 2 的幂。**十进制小数常常在二进制里是无限循环小数**——这就是 0.1 + 0.2 ≠ 0.3 的种子，下一课拆开看它的位。

### §2.2 补码：一条恒等式，不是一句口诀

**从钟表开始。**12 点制的钟，现在是 11 点，你想退回 3 小时前：11 − 8 = 3；也可以 11 + 4 = 15，15 对 12 取模还是 3。**在 mod 12 的世界里，减 8 等于加 4**——因为 4 ≡ −8 (mod 12)。减法从来不需要单独的电路，加一个数、丢掉越界的部分，效果一样。

**8 位世界就是 mod 256。**8 位只有 256 个位串，任何运算的结果都绕不出这个圈——第 9 位（256）没地方放，直接丢。于是：

- `−1 ≡ 255`，一般地 `−x ≡ 256 − x`。
- 机器算 `3 − 1`：先变成 `3 + 255 = 258 = 256 + 2`，丢掉 256，剩 **2**。加法器一套搞定。

**"取反加一"的真相。**对 0 ≤ x ≤ 255，按位取反 = 每位用 1 减 = `1111 1111 − x = 255 − x`；再加一，就是 **256 − x**。所以口诀"取反加一"根本不是规定，它是恒等式

```text
~x + 1 = 256 − x   （8 位语境；n 位就把 256 换成 2ⁿ）
```

的位级写法。补码 = "用模减出来的那个数"。推论马上来：**补码的补码**——`256 − (256 − x) = x`，正数取反加一两次必然还原。以后忘了任何口诀，回到这条恒等式现推。

**−128 为什么特殊。**int8 的范围是 −128 ~ 127，负的比正的多一个。用模的眼光看：−128 的"模补"是 256 − 128 = **128**——而 +128 不在 int8 里（上限 127）。所以 `1000 0000` 取反加一：`0111 1111 + 1 = 1000 0000`，转一圈回到自己，正如 §1.1 的 B 题。数一数位串的分配就平衡了：负数 −128 ~ −1 占 128 个位串，0 和正数 0 ~ 127 占另外 128 个——256 个位串一个不浪费。

**减法变加法的完整链条**（ex2 的 TODO 5 就是它）：

```text
a − b = a + (256 − b) = a + (~b + 1)   (mod 256)
```

### §2.3 符号扩展与溢出判定

**一个值公式，今天会直接变成代码。**8 位补码位串的值：

```text
值 = 无符号读法 u − 256 × 符号位 s
```

`1111 1111`：u = 255，s = 1，值 = 255 − 256 = **−1**。这个公式说明：补码和无符号**共用同一套位串**，差别只在"最高位按 −256 还是 +128 计入"。ex2 的 `signed8` / `unsigned8` 就是它的两个分支。

**符号扩展：int8 → int16，复制符号位。**`−1`（8 位全 1）扩成 16 位：`1111 1111 1111 1111`——用值公式验：65535 − 65536 = −1 ✓。为什么复制 0 不行？拿 −128 试：补 0 得 `0000 0000 1000 0000` = +128，值变了；补 1 得 `1111 1111 1000 0000`，65408 − 65536 = −128 ✓。直觉版说法：前面那些 1 表示"还欠着 256（的更高次幂）"，扩展时欠账要一起搬过去。§1.1 的 D 题 `(0xFF << 24) >> 24`，就是靠算术右移复制符号位做扩展的现场版。

**溢出判定：只看符号位——同号相加得异号，即溢出。**

- `100 + 50`：`0110 0100 + 0011 0010 = 1001 0110`。正 + 正 = 负 → **溢出**（结果 int8 读作 −106）。
- `−100 + (−50)`：`1001 1100 + 1100 1110 = 1 0110 1010`，丢第 9 位得 `0110 1010`。负 + 负 = 正 → **溢出**（本该是 −150）。
- 一正一负相加**永不溢出**：两个异号数的和，绝对值不会超过其中绝对值大的那个，必然还在圈内。

硬件视角（第 3 课的加法器就长这样）：溢出判定不需要知道"值"是多少，**只看两个操作数的符号位和结果的符号位**——同号入、异号出，一根异或门就接得出来。

**减法怎么办？**转成加法（`a + (−b)`）后按加法判。但注意 `−b` 本身可能编不出来：b = −128 时 −b = +128 超出 int8——ex2 里这个边界要你亲手接住。

### §2.4 carry 和 overflow：一套电路，两个标志

8 位加法做完，其实产生了两个彼此独立的"越界报告"：

- **carry（进位）**：向第 9 位进出去的那一位——模运算里"丢掉的 256"。它是**无符号语境**的溢出信号。
- **overflow（溢出）**：§2.3 的符号位判定。它是**有符号语境**的溢出信号。

四个例子把四种组合摆全：

| 例子（8 位）                  | 位串加法            | carry | overflow |
| ----------------------------- | ------------------- | ----- | -------- |
| 1 + 2（两边都没事）            | `0000 0011`         | 0     | 0        |
| 255 + 1（uint 溢出；int8 是 −1+1=0，正常） | `1 0000 0000` | 1     | 0        |
| 100 + 50（uint 正常 150；int8 溢出）      | `1001 0110`   | 0     | 1        |
| −128 + (−128)（两边都溢）      | `1 0000 0000`       | 1     | 1        |

一句话记牢：**硬件加完并不知道你按哪种语境用它**——它把两个标志都算好放在那里，无符号的人看 carry，有符号的人看 overflow。"说清编码语境"不是哲学要求，是读标志位的前提。

### §2.5 JS/TS 语境：位运算的三个坑

写今天两个练习之前，你得知道 JS 的位运算在哪个世界里干活：

1. **Number 没有整数。**JS 里所有数都是 IEEE 754 double（下一课主角），`1` 和 `1.0` 是同一个数。所以"8 位机器"今天要用**位串（0/1 字符串）**自己搭，而不是指望 Number 替你管位宽。
2. **位运算按 32 位补码做。**参与 `& | ^ << >>` 前，操作数先被转成 int32（这步叫 ToInt32），算完再转回 Number。于是 `0xFFFFFFFF | 0` 是 **−1**，不是 4294967295——位运算的结果永远先落在 32 位补码语境里。
3. **`>>>` 是唯一的无符号出口。**无符号右移把结果按 uint32 读：`(-1) >>> 0` = 4294967295。第 2 课看浮点位模式时它还会出场。

今天用得上的惯用法一个：**取低 8 位、按无符号读：`x & 0xFF`**（`-1 & 0xFF` = 255）。掩码的思想就一句话——"只留我要的位，其他清零"。

> 💡 **ex2 的实现策略（先想清楚再动手）**
> 推荐全程用 0/1 字符串手写位级运算（encode / addBits / 解码各一个函数）——今天的主角是位，不是 Number 技巧；而且这套按位加法，就是第 3 课 Nand2Tetris 里 FullAdder/Add16 芯片的预演，写了不亏。想用 Number 做辅助（比如先验算）也行，但每一步都要 `& 0xFF` 掩码，并且能说出这一步在哪个语境里。

### 任务 3 · ex2 补码运算器（25 分钟）

自测五题（每题先默答，再点开「看答案」）：

**Q1. 位串 `1000 0000` 在 int8 / uint8 语境下各是什么值？为什么 −128 没有对应的正数？**

> [!question]- 看答案（先默答再点开）
> **−128 / 128。**值公式：u − 256×s——u = 128，按 int8 读是 128 − 256 = −128，按 uint8 读就是 128。−128 的"模补"是 256 − 128 = 128，而 +128 超出 int8 上限 127，编不出来——所以 `1000 0000` 取反加一回到自己，负数比正数恰好多占一个位串。

**Q2. "取反加一"背后的恒等式是什么？**

> [!question]- 看答案（先默答再点开）
> **`~x + 1 = 2ⁿ − x`（8 位就是 256 − x）。**按位取反 = 全 1 减 x = 255 − x；再加 1 就是 256 − x，即"用模减它"。补码不是表示负数的技巧，是模运算恒等式的位级写法——由此还能自推：补码的补码回到原数（256 − (256 − x) = x，x ≤ 127 时）。

**Q3. 8 位里 127 + 1 得到什么？carry 是多少？overflow 呢？**

> [!question]- 看答案（先默答再点开）
> **位串 `1000 0000`：uint8 读 128，int8 读 −128；carry = 0（第 9 位没有进出去）；overflow = 1（正 + 正 = 负）。**注意它和 255 + 1 的区别：那个 carry = 1、overflow = 0——两个标志独立工作，各管一个语境。

**Q4. JS 里 `(-1) >>> 0` 为什么是 4294967295？**

> [!question]- 看答案（先默答再点开）
> **位运算在 32 位补码里做，`>>>` 把结果按 uint32 读。**−1 的 32 位补码是 32 个 1；按无符号读就是 2³² − 1 = 4294967295。位串没变，换的只是语境——本课核心认知的现场重演。

**Q5. 0.6875 四步就转完了，0.1 为什么永远转不完？**

> [!question]- 看答案（先默答再点开）
> **0.6875 = 11/16，分母是 2 的幂，二进制小数有限位装得下；0.1 = 1/10，分母含素因子 5，乘 2 取整的过程进入循环（0.1→0.2→0.4→0.8→0.6→0.2…），二进制是无限循环小数。**有限位存不下无限循环——只能截断，截断就是误差，0.1 + 0.2 ≠ 0.3 的种子在这里。下一课拆它的位。
