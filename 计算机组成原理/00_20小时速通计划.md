# 计算机组成原理 20 小时速通计划

> 目标：用 10 次 × 2 小时，掌握计算机组成原理最重要的 20%——**先手算、再对拍**，能从一条高级语言语句出发，讲清它在硬件上走完全程的每一步。
> 前置要求：TypeScript 课程的基础（练习用 `npx tsx` 直跑，仓库根目录环境直接复用）；不需要数字电路基础；**零硬件、零安装**——Nand2Tetris 全程用[网页版 IDE](https://nand2tetris.github.io/web-ide/)。
> 与 [00_学习路线图.md](00_学习路线图.md) 的关系：那份是 4–6 个月的完整路线，本计划是它的浓缩核心——等级 1 全部、等级 2 概念 + 尝鲜、等级 3 的核心、等级 4 的手算与迷你模拟、等级 5 换成讲解式毕业。20 小时后想深入，从长期路线的等级 2 / 3 接着走。
> 练习编号接续路线图：ex1–ex4 就是路线图等级 1 的四个练习；ex5（手算题）拆散融入各次课，过程统一记 NOTES.md；新写的 TS 练习从 ex6 起编号（路线图等级 3–4 的练习未占编号）。

## 怎么用这份计划

- **每次的节奏**：约 30 分钟学（读学前阅读）→ 80 分钟练（手算 + 写代码）→ 10 分钟复盘。
- **本课程的底线——先手算，再对拍**：所有位运算、编码、cache 划分、流水线题，先在纸上写出过程，再用程序验证。"程序算出来了"不算会，"手算对了、程序只是确认"才算会。手算过程统一记进 `NOTES.md`。
- **第二条底线——说清编码语境**：写下任何一个位串答案，都要能说出它"在什么编码语境下是什么值"（无符号？int8？浮点？）。这条贯穿 10 次。
- **复盘的正确姿势**：合上笔记，先凭记忆把复盘问题的答案**口述或写下来**，再打开验证。"感觉我知道"不算数——能说出来才是真的会。
- **建议隔天一次**，3–4 周完成。间隔重复比连续突击记得牢得多。
- **卡住超过 20 分钟**就求助：把你期望什么、实际发生什么、完整过程贴给 AI 导师（也就是我），别自己耗着。
- 练习做不完就压缩范围，**但复盘不能跳过**。
- 完成一项练习就把 `[ ]` 勾成 `[x]`。

## 最重要的 20% 是什么

计算机组成原理可以讲一整年——门电路、微程序控制器、总线仲裁、外设……但真正决定你"懂不懂计算机"的就那么几样。以下 8 项就是那关键的 20%：

| #   | 核心内容                                   | 为什么重要                                       |
| --- | -------------------------------------- | --------------------------------------------- |
| 1   | 位与补码：数即位串、模运算、溢出                      | 一切的地基。不懂"位串的值取决于编码约定"，你看类型转换、溢出 bug 时永远在猜 |
| 2   | IEEE 754 浮点数：布局、移码、特殊值                 | 解释 0.1 + 0.2 ≠ 0.3、精度事故——日常工程里出现频率最高的"组成原理时刻" |
| 3   | 存储程序与指令周期：取指—译码—执行—写回                  | 全课程的中心叙事。后面所有内容都是在这个循环上做文章 |
| 4   | 汇编与栈帧：寄存器、call/ret、栈（godbolt 对照）        | 亲眼看到高级语言的变量、函数、递归在机器层面是什么；调试与性能分析能力的根 |
| 5   | 存储层次与局部性：金字塔、时间/空间局部性                  | 程序性能第一定律——理解了局部性，才知道为什么代码"这样写快、那样写慢" |
| 6   | cache 三件套：地址划分、映射与相联度、写策略              | 考研面试的硬通货；真实性能优化（分块、按行遍历）背后的原理 |
| 7   | 流水线与三类冒险：forwarding、stall、分支预测          | 现代 CPU 跑得快的本质；解释"为什么乱序数据比循环依赖慢"这类现象 |
| 8   | 性能思维：CPI、AMAT、加速比                      | 用数据谈性能，而不是用感觉——所有优化的度量衡 |

### 明确砍掉的 80%（20 小时内不碰或只到概念级）

- **门级电路设计全量**：Nand2Tetris Projects 1–3 的完整芯片树、超前进位加法器——只尝鲜 4 个芯片建立直觉，完整版在长期路线等级 2
- **自己写完整汇编器 / CPU 模拟器**：长期路线等级 3–4 的主力练习（Hack 汇编器、周期级模拟器），20 小时内装不下，也不划算
- **浮点运算的电路实现**：乘除法器、舍入的硬件细节——会用、会算、会解释就够
- **虚拟存储 / TLB / 页表细节**：知道"它是内存层的 cache"这个类比即可，展开在等级 4 和操作系统课
- **总线仲裁、外设控制器、I/O 接口电路**：中断与 DMA 只到概念级（第 10 次导览）
- **RISC-V 指令逐位编码**：R / I / S / B / U / J 五种格式的位级布局不背，能读懂汇编即可
- **微程序控制器 vs 硬布线的实现细节、RISC/CISC 演化史**：知道取舍结论就行

这些不是不学，是现在不学——长期路线图（[00_学习路线图.md](00_学习路线图.md)）里都有安排。

## 10 次课

### 第 1 次 · 位与补码——机器里的整数

> **核心认知：计算机里没有"数"，只有位。同一个位串是什么值，取决于编码约定。补码用模运算让加减法共用一套电路。**

- 代码放：`01_数据的表示/`（上课时创建）
- 学前阅读（约 30 分钟）：CSAPP 第 2.1–2.3 节（信息的存储、整数的表示）；或让 AI 导师 20 分钟讲一遍"模运算视角的补码"；通勤路上配 Crash Course 计算机科学速成课（B 站搜）第 4–5 集

**学习目标**
- 二 / 八 / 十 / 十六进制互转不查资料，含小数部分（乘 2 取整）
- 从模的角度讲清补码：为什么取反加一、为什么减法变加法、为什么 −128 没有对应的正数
- 符号扩展；用"同号相加得异号"判溢出
- 分清 carry（进位）与 overflow（溢出）：无符号看前者，有符号看后者

**练习任务（80 分钟）**
- [ ] （15 分钟）手算热身 8 题：进制转换 4 题（含 1 题小数部分）+ 补码运算判溢出 4 题，过程记进 NOTES.md
- [ ] （40 分钟）ex1 进制转换器：十进制 ↔ 二进制 / 十六进制，整数和小数部分手动实现，禁用 `parseInt(s, 2)` 和 `toString(16)` 一步到位
- [ ] （25 分钟）ex2 补码运算器：8 位补码加减法，输入输出都显示位串，并正确报告是否溢出——用刚才的手算题当测试用例对拍

**复盘问题**
1. 不看笔记，从"模"的角度讲清：补码为什么能让减法变成加法？
2. `0xFF` 在哪几种编码语境下分别是什么值？
3. carry 和 overflow 的区别是什么？做 8 位运算时，谁该看哪个标志？

### 第 2 次 · IEEE 754——浮点数的真相

> **核心认知：浮点数用精度换范围。0.1 + 0.2 ≠ 0.3 不是 bug，是位级事实。**

- 代码放：`01_数据的表示/`
- 学前阅读（约 30 分钟）：CSAPP 第 2.4 节（浮点数）；重点看规格化公式和特殊值，跳过舍入模式

**学习目标**
- 单 / 双精度布局 1+8+23 / 1+11+52；阶码用移码（偏置 127 / 1023）及原因
- 规格化公式 (−1)^s × 1.M × 2^(e−bias)；±0、±∞、NaN、非规格化数分别对应阶码全 0 / 全 1
- 说清十进制小数为什么常常无法精确表示成二进制（分母含 2 以外的素因子）
- 区分机器精度 ε 与"能表示的最小正数"

**练习任务（80 分钟）**
- [ ] （15 分钟）手算：−0.15625 和 0.5 的单精度编码 + 一道"位串 → 浮点数"解码，过程记 NOTES.md
- [ ] （45 分钟）ex3 IEEE 754 观察站：用 `DataView` 打出 0.1、0.2、−0、∞、NaN 的位模式；再手写"位串 → 浮点数"解码函数，与 JS 引擎结果对拍
- [ ] （20 分钟）ex4 精度实验：找出 1 + ε > 1 的最小双精度 ε（机器精度），并解释它和阶码位宽的关系；顺带在位级展示 0.1 + 0.2 到底加出了什么

**复盘问题**
1. 手推 0.1 的双精度位模式（写出符号、阶码、尾数的前几位即可）。
2. 阶码为什么用移码而不是补码？好处是什么？
3. 机器精度 ε 和"能表示的最小正数"是一回事吗？差在哪？

### 第 3 次 · 从与非门到内存——机器怎么"记住"

> **核心认知：组合逻辑负责"算"（输出只由当前输入决定），时序逻辑负责"记"（靠时钟沿同步更新状态）。时钟是整台机器的心跳。**

- 代码放：`02_数字逻辑/`（上课时创建；手画的真值表拍照、HDL 文件从网页版导出都存这里）
- 学前阅读（约 30 分钟）：[Nand2Tetris](https://www.nand2tetris.org) 配套书第 1 章（布尔逻辑）+ 第 3 章前半（时序电路）；或 Crash Course 第 5–7 集（布尔逻辑、ALU、寄存器）
- 工具：全程用[网页版芯片仿真器](https://nand2tetris.github.io/web-ide/chip/)，不需要装 Java

**学习目标**
- 基本门 + 德摩根律；Mux / DMux——"按地址选一个"的基本功
- 加法器链路：半加器 → 全加器 → 16 位行波进位
- DFF → 寄存器 → RAM 阵列 → PC；边沿触发，输出是"上一个时钟沿之前输入的函数"
- 能说出 PC 三个控制位（inc / load / reset）的优先级设计理由

**练习任务（80 分钟）**
- [ ] （15 分钟）手画：全加器真值表 + 电路图（两个 XOR、两个 AND、一个 OR），并用真值表证明一次德摩根律，记 NOTES.md
- [ ] （45 分钟）Nand2Tetris 网页版尝鲜：写 Xor、Mux、FullAdder、Add16 四个芯片的 HDL，跑绿官方测试——只做这 4 个，这是刻意裁剪：完整 Projects 1–2 属于长期路线等级 2
- [ ] （20 分钟）读 PC 芯片规格，口头讲清三个控制位的优先级为什么那样设计（讲给 AI 导师听，要点记 NOTES.md）

**复盘问题**
1. 1 位是怎么"存"住的？从 DFF 的输出反馈讲起。
2. 为什么时序电路必须靠时钟沿对齐，不能靠"信号传到了"？（提示：门延迟）
3. RAM 的读和写，本质上分别靠哪两个基本部件？

### 第 4 次 · 存储程序与 Hack 汇编——CPU 的母语

> **核心认知：机器码只是约定好的位模式。存储程序 = 指令和数据躺在同一块内存里，CPU 一条条取出来解释。**

- 代码放：`03_指令与汇编/`（上课时创建）
- 学前阅读（约 30 分钟）：[Nand2Tetris](https://www.nand2tetris.org) 配套书第 4 章前半（Hack 机器语言：A / C 指令、寻址）；配 Crash Course 第 8–9 集
- 工具：[网页版 CPU 仿真器](https://nand2tetris.github.io/web-ide/cpu/)

**学习目标**
- 冯·诺依曼结构：存储程序、取指—译码—执行—写回的循环
- Hack 的 A 指令（@value）与 C 指令（dest=comp;jump）；A 寄存器的双重角色（存地址 / 存常量）
- 内存映射 I/O：SCREEN、KEYBOARD 就是一段普通内存
- 会用 CPU 仿真器单步执行并观察 A / D / PC 的变化

**练习任务（80 分钟）**
- [ ] （20 分钟）单步观察：加载仿真器自带示例程序，单步 20 个周期，记录每个周期 A / D / PC 的值，标出当前处于取指阶段还是执行阶段
- [ ] （50 分钟）手写 Hack 汇编：从 `RAM[0]` 读入 n，计算 1×2×…×n 或斐波那契第 n 项，结果写进 `RAM[1]`（存成 `03_指令与汇编/mult.asm`，对应路线图等级 3 的"手写小程序"练习）
- [ ] （10 分钟）点亮屏幕：往 SCREEN 映射区域写位，让仿真器屏幕上出现一条竖线——体会"屏幕就是内存"

**复盘问题**
1. A 寄存器的双重角色是什么？为什么 Hack 的设计离不开它？
2. "存储程序"和"把程序焊死在电路里"（如老式计算器）差在哪？
3. 单步执行时，你靠什么区分 CPU 当前在取指还是在执行？

### 第 5 次 · 函数调用的机器真相——栈帧与寄存器

> **核心认知：高级语言里的变量和函数，在机器层面不存在——只有寄存器和地址。函数调用 = 跳转 + 在栈上开一个帧。**

- 代码放：`03_指令与汇编/`（注解与结论存 `godbolt_notes.md`）
- 学前阅读（约 30 分钟）：CSAPP 第 3.4–3.7 节选读（重点 3.7 过程调用一节：call / ret、栈帧）；先让 AI 导师 10 分钟讲一遍 [godbolt.org](https://godbolt.org) 的用法（选编译器、加 -O0、看颜色对应）

**学习目标**
- 看懂 -O0 汇编的骨架：参数进哪个寄存器、返回值放哪、call / ret 干什么、栈帧怎么开合
- caller-saved 与 callee-saved 的区别（以 RISC-V 的 ra / sp 为参照）
- 递归的机器级实现：每次调用压一个栈帧，栈就是递归的"账本"
- 建立直觉：内存里没有名字，只有地址

**练习任务（80 分钟）**
- [ ] （50 分钟）godbolt 对照实验 4 个 C 函数：两数相加、for 循环累加、函数调用（多参数）、递归阶乘——编译器选 RISC-V gcc、-O0，逐行注解汇编（参数在哪、返回值在哪、栈帧开多大、递归的 call 在哪、栈指针怎么动），写成 `godbolt_notes.md`
- [ ] （30 分钟）内存视角实验：写 C 小程序打印局部变量的地址——同一函数调用两次，地址相同吗？递归到第 3 层呢？用"栈帧开合"解释观察到的现象

**复盘问题**
1. call 和 ret 分别做了什么？ra 里保存的是谁？
2. 递归和循环在机器层面的本质区别是什么？递归为什么"深了会爆栈"？
3. 为什么局部变量"函数一返回就没值了"？它住在哪？

### 第 6 次 · 数据通路——一条指令的完整旅程

> **核心认知：CPU = 数据通路 + 控制信号。每条指令是一次精心编排的电路活动，控制器本质是"指令 → 控制位"的查表。**

- 代码放：`04_CPU与存储/`（上课时创建；trace 表格存这里）
- 学前阅读（约 30 分钟）：[Nand2Tetris](https://www.nand2tetris.org) 配套书第 5 章前半（只读数据通路图，不写 HDL）；配 Crash Course 第 8 集

**学习目标**
- Hack CPU 的组成：A / D 寄存器、ALU、PC，各自的角色
- 一条 C 指令的完整周期：取指 → 译码 → 读寄存器 / 内存 → ALU → 写回或跳转
- 控制信号怎么来：指令位模式 → 控制位的查表
- 知道 RISC-V 把一个周期切成五段（IF / ID / EX / MEM / WB）——为第 9 次流水线埋伏笔

**练习任务（80 分钟）**
- [ ] （40 分钟）画图：纸上 / 白板画出 Hack 数据通路，然后执行 `D=D+M; JGT`——标出每个部件此刻的输入、输出和控制位的值
- [ ] （30 分钟）trace 实验：在 CPU 仿真器跑一段含跳转的小程序，逐周期记录表格（周期号 / PC / A / D / ALU 输出 / 是否跳转），存 `04_CPU与存储/trace_notes.md`
- [ ] （10 分钟）对照口述：同一条加法在 RISC-V 五段数据通路上要怎么走？（口述给 AI 导师，要点记 NOTES.md）

**复盘问题**
1. 讲清 `D=D+M` 从取指到写回的完整旅程，每个阶段用了数据通路上哪些部件。
2. 控制器在干什么？为什么说它"本质是查表"？
3. Hack 一个周期干完的事，RISC-V 为什么要切成五段？（提示：想想流水线）

### 第 7 次 · 存储层次与局部性——为什么有 cache

> **核心认知：快、大、便宜不可兼得。存储层次用局部性换速度——程序倾向反复用刚用过的数据（时间局部性）和它旁边的数据（空间局部性）。**

- 代码放：`04_CPU与存储/`
- 学前阅读（约 30 分钟）：CSAPP 第 6.1–6.2 节（存储技术、局部性）；配 Crash Course 第 19 集（内存与存储）

**学习目标**
- 层次金字塔：寄存器 / L1–L3 cache / 内存 / SSD，各层延迟的数量级（寄存器 ~1ns、内存 ~100ns、SSD ~100μs）
- 给一段代码标注时间 / 空间局部性的好坏（按行 vs 按列遍历数组）
- 直接映射的地址划分：offset 由块大小决定、index 由行数决定、剩下是 tag
- 会判断一串地址的命中与缺失

**练习任务（80 分钟）**
- [ ] （15 分钟）手算：延迟数量级排序 5 项 + 判断两段循环代码（按行 / 按列遍历大数组）的局部性，记 NOTES.md
- [ ] （35 分钟）手算 4 题：给定 cache 容量与块大小，划分 32 位地址的 tag / index / offset；对一串地址判断直接映射下命中与否——过程记 NOTES.md
- [ ] （30 分钟）ex6 cache 划分器（`ex6_cache_divider.ts`）：输入容量 / 块大小 / 地址，输出三段划分与命中判断，用刚才的手算题对拍

**复盘问题**
1. 按列遍历大数组为什么比按行慢？从"一个 cache 行装多少数组元素"讲到位级。
2. index 位数由谁决定？tag 位数呢？两者此消彼长的关系是什么？
3. cache 行里的 tag 到底在拿什么和什么比较？

### 第 8 次 · 相联度、写策略与 AMAT——cache 深水区

> **核心认知：直接映射的冲突缺失，可以用相联度来换；写策略决定数据什么时候真正落回内存。性能要用 AMAT 算，不能靠感觉。**

- 代码放：`04_CPU与存储/`
- 学前阅读（约 30 分钟）：CSAPP 第 6.3–6.4 节前半（存储层次、cache 的组织）；LRU 演练让 AI 导师出题带练

**学习目标**
- 直接映射 / 组相联 / 全相联的取舍：冲突缺失 vs 查找成本
- LRU 替换的演练；脏位是什么、为什么配套 write-back
- write-through vs write-back、write-allocate vs no-allocate 的适用场景
- AMAT = 命中时间 + 缺失率 × 缺失代价；含 cache 的 CPI 计算

**练习任务（80 分钟）**
- [ ] （20 分钟）手算：同一地址串在直接映射 vs 2 路组相联下的命中率对比 + LRU 逐次演练，过程记 NOTES.md
- [ ] （50 分钟）ex7 迷你 cache 模拟器（`ex7_cache_sim.ts`）：读入地址 trace 文件，先实现直接映射输出命中率；再扩展 2 路组相联 + LRU + write-back 脏位统计；同一 trace 横向对比两种组织
- [ ] （10 分钟）用模拟器的数据解释：这组 trace 下 2 路比直接映射好多少？什么情况下差距会消失？

**复盘问题**
1. 脏位为什么是 write-back 的配套机制？write-through 需要它吗？
2. AMAT 公式的三项分别对应硬件的什么参数？哪个通常占大头？
3. 什么工作负载下，增大块大小反而让性能变差？（提示：缺失 penalty 与空间局部性）

### 第 9 次 · 流水线——让 CPU 跑得快

> **核心认知：流水线不缩短单条指令的延迟，但提高吞吐。冒险（hazard）是流水线的天敌。**

- 代码放：`04_CPU与存储/`（时空图拍照或画成表存这里）
- 学前阅读（约 30 分钟）：无重阅读材料——让 AI 导师 30 分钟讲五段流水线与三类冒险（中文教材这章普遍繁琐，导师浓缩版更省时；想读可查袁春风《计算机组成与系统结构》流水线一章）

**学习目标**
- IF / ID / EX / MEM / WB 五段；吞吐与延迟的区别；加速比怎么算
- 三类冒险：结构、数据（RAW、load-use）、控制；对策：forwarding、stall、分支预测
- 说清 forwarding 为什么救不了 load-use（差的是哪一拍）
- CPI 计算：理想 1.0，加上各类停顿逐项累加

**练习任务（80 分钟）**
- [ ] （35 分钟）画 2 张时空图：8 条无冒险指令 vs 含 1 个 load-use + 1 个分支的指令序列——各自数出总周期数与 stall 数
- [ ] （25 分钟）手算 CPI：给指令占比（load 30%、分支 15%…）与各类停顿周期，算整体 CPI、与单周期版对比的加速比，过程记 NOTES.md
- [ ] （20 分钟）重排指令：给一小段含冒险的汇编，只调整顺序不改变语义，消掉 stall——重画时空图验证周期数下降

**复盘问题**
1. 流水线为什么不能降低单条指令的延迟？它提升的到底是什么？
2. forwarding 为什么救不了 load-use？数据差的是哪一拍、谁等谁？
3. 分支预测猜错的代价是什么？为什么现代 CPU 愿意为此砸几十亿晶体管？

### 第 10 次 · 毕业串联——一条 a+b 的一生

> **核心认知：学完组成原理的标志：能从一条高级语言语句出发，讲清它在硬件上走完全程。**

- 代码放：`04_CPU与存储/`（毕业讲解文档放这里）
- 学前阅读：无新材料——把 9 次课的 NOTES.md 手算题重读一遍，这本身就是最好的复习

**学习目标**
- 串联全链路：C 语句 → 编译成什么指令 → 指令和数据怎么被取出（顺带讲 cache 局部性）→ 五段流水线怎么流 → 结果写回哪
- 概念级补全系统拼图：中断与 DMA 的区别（轮询 vs 打断 CPU vs 抢总线）、虚拟存储是什么的类比

**练习任务（80 分钟）**
- [ ] （10 分钟）导览：让 AI 导师 10 分钟讲中断与 DMA（要点记 NOTES.md），把最后一块拼图放上
