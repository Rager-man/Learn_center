# 计算机组成原理五级学习路线

> 目标：从完全新手到能独立做项目——自己定义一台计算机，并亲手把它造出来（软件模拟器路线）。业余时间约 4–6 个月。
> 前置要求：会任意一门语言（Python / TypeScript 都行，本仓库练习用 TS 写）；不需要数字电路基础；不需要买任何硬件。
> 主线工具：Nand2Tetris（免费，官网 www.nand2tetris.org，硬件模拟器需装 Java，也有网页版 IDE）+ 仓库自带的 `npx tsx`。
> 与 TypeScript 课程的关系：等级 1、3、4、5 的练习全部用 TypeScript 写——进制转换器、汇编器、CPU 模拟器、cache 模拟器都是 TS 程序，TS 那边等级 3 以后的能力在这里直接复用，两门课互相喂。
> 用法：每完成一项练习或达标一项标准，把 `[ ]` 改成 `[x]`。所有晋级标准打勾后，再进入下一等级。

## 等级 1：数据表示与编码——机器里的数（约 2–3 周）

**核心认知：计算机里没有"数"，只有位。同一个位串是什么数，取决于你怎么解读它（编码约定）。补码让加减法共用一套电路，浮点数用精度换范围。**
这个认知没建立，后面学 ALU、看类型转换、排查浮点 bug 时，你会一直在"猜"而不是"算"。

### 需要掌握
- 进制转换：二进制 ↔ 八进制 ↔ 十六进制 ↔ 十进制，整数部分和小数部分都要会（小数部分是乘 2 取整）
- 补码：n 位范围 −2^(n−1) ～ 2^(n−1)−1；求补（取反加一）背后的模运算原理；符号扩展；为什么补码能让减法变成加法；为什么 −128 没有对应的正数
- 溢出：同号相加得异号才是溢出；carry（进位）和 overflow（溢出）是两回事
- 定点数：小数点位置固定的表示，理解它是浮点数的对照物
- IEEE 754：单精度 1+8+23 / 双精度 1+11+52；阶码用移码（偏置 127 / 1023）及原因；规格化形式；±0、±∞、NaN、非规格化数分别对应阶码全 0 / 全 1
- 字符编码：ASCII、Unicode 码点与 UTF-8 变长编码的关系（概念级）

### 常见错误
- 把位串和值混为一谈：0xFF 在无符号语境是 255，在 int8 语境是 −1，在 double 里啥都不是
- 补码"取反加一"背得滚瓜烂熟，问"补码的补码是什么、为什么"就卡壳
- 判断溢出只会背"结果超出范围"，手算时不会用"同号相加、结果变号"来检查
- 把 carry 和 overflow 混为一谈：无符号运算看进位，有符号运算看溢出，两个标志互相独立
- 0.1 + 0.2 ≠ 0.3 归咎于"浮点数有 bug"——说不清十进制小数为什么无法精确表示成二进制（分母含 2 以外的素因子）
- 不知道 IEEE 754 阶码全 0 / 全 1 被特殊值占用，套公式算 0 或极小数的编码，得出错误答案

- [ ] ex2 补码运算器：8 位补码加减法，输入输出都显示位串，并正确报告是否溢出
- [ ] ex3 IEEE 754 观察站：用 `DataView` 打出 0.1、0.2、−0、∞、NaN 的位模式；再手写"位串 → 浮点数"解码函数，与 JS 引擎结果对拍
- [ ] ex4 精度实验：找出 1 + ε > 1 的最小双精度 ε（机器精度），并解释它和阶码位宽的关系
- [ ] ex5 手算题（过程记进 NOTES.md）：每类至少 5 题——进制转换、补码运算判溢出、IEEE 754 编解码

## 等级 2：数字逻辑——从门电路到内存（约 3–4 周）

**核心认知：再复杂的计算机也是与非门和时钟搭出来的。组合逻辑负责"算"（输出只由当前输入决定），时序逻辑负责"记"（靠时钟沿同步更新状态）。时钟是整台机器的心跳。**

### 需要掌握
- 布尔代数：真值表、德摩根律、与或非表达式的化简
- 常见门：AND / OR / NOT / NAND / NOR / XOR；为什么 NAND 是"万能门"
- 多路选择器 Mux 与分配器 DMux / 译码器 Decoder——"按地址选一个"的基本功
- 加法器链路：半加器 → 全加器 → 16 位行波进位 → 超前进位的改进思路（概念）
- ALU 的控制位思想：同一坨电路，靠控制位决定它这次做加、做减还是比较大小
- 时序元件：D 触发器（DFF）→ 寄存器 → RAM 阵列 → 程序计数器 PC
- 时钟：电平触发 vs 边沿触发；为什么时序芯片的输出是"上一个时钟沿之前输入的函数"
- 工具链：Nand2Tetris 硬件模拟器、HDL 语法、测试脚本（.tst + .cmp）怎么跑

### 常见错误
- 以为信号"瞬间"传遍电路，忽略门延迟——不理解时序电路为什么必须靠时钟沿对齐
- 锁存器和触发器分不清，电平触发和边沿触发混着说
- 写 HDL 时忘了内部管脚要先声明，或者把输出当输入用
- 搭 RAM 时把"地址选行"想得过于玄乎——本质就是 DMux 选通写入 + Mux 选出读出
- 真值表都懒得画就背化简公式，遇到没见过的电路直接卡住
- 把 Nand2Tetris 的内置芯片当黑盒不敢拆——这一级的目的就是拆开它

### 练习（代码放 `02_数字逻辑/`，Nand2Tetris HDL）
- [ ] Project 1：Not / And / Or / Xor / Mux / DMux 及其 16 位版本
- [ ] Project 2：HalfAdder / FullAdder / Add16 / Inc16 / ALU
- [ ] Project 3：Bit / Register / PC / RAM8 → RAM16K
- [ ] 补充：在 NOTES.md 用真值表证明德摩根律；把一个 4 输入电路手工化简到最简与或式
- [ ] 每个芯片写完立刻跑官方 .tst 对比 .cmp，全绿才算过

### 晋级标准

- [ ] 能解释 1 位是怎么"存"住的：DFF 的输出反馈 + 时钟沿更新
- [ ] 能说出 PC 三个控制位（inc / load / reset）的优先级为什么那样设计

## 等级 3：指令系统与汇编——CPU 的母语（约 3–4 周）

**核心认知：机器码只是约定好的位模式，ISA 是硬件与软件之间的合同。汇编让你亲眼看到高级语言里的 for 循环、函数调用、指针，在机器层面到底是什么。**

### 需要掌握
- 冯·诺依曼结构：存储程序、取指—译码—执行—写回的循环
- Hack 机器语言：A 指令（@value）与 C 指令（dest=comp;jump）、地址寄存器 A 的双重角色、屏幕与键盘的内存映射
- 对照 RISC-V RV32I 子集：x0 恒为 0、ra / sp 的角色、R / I / S / B / U / J 五种指令格式、立即数的符号扩展
- 汇编编程三件套：分支与循环、函数调用与返回、栈帧（保存 ra、caller / callee-saved 寄存器、局部变量放栈上）
- 递归的机器级实现：每次调用压一个栈帧
- 寻址方式：立即数 / 寄存器 / 直接 / 间接 / 基址偏移
- 汇编器原理：两遍扫描——第一遍收集标号地址，第二遍生成机器码；符号表是什么
- RISC 与 CISC 的设计取舍（为什么现代芯片都是 RISC 血统）

### 常见错误
- 函数调用忘保存 ra，返回时跳到天边；忘恢复用过的 callee-saved 寄存器
- caller-saved 和 callee-saved 不区分，子函数一返回自己的变量就没了
- 循环边界 off-by-one——汇编没有编译器帮你查，跳转得自己数
- 用高级语言的"变量"直觉理解内存：内存里没有名字，只有地址
- 立即数超出编码范围硬塞，位宽错位整条指令都废
- 写汇编器只做一遍扫描，遇到前向引用的标号（跳到还没见过的 label）就懵

- [ ] ex: 用 TypeScript 写完整 Hack 汇编器（对照官方 Project 6 规格）：两遍扫描 + 符号表（预定义符号 / 标号 / 变量），通过官方全部测试

## 等级 4：CPU 与存储层次——造一台 CPU，再让它跑得快（约 1.5–2 个月）

**核心认知：CPU = 数据通路 + 控制信号，每条指令是一次精心编排的电路活动。存储层次是对"快 vs 大 vs 便宜"矛盾的回答——cache 用局部性换速度。**

### 需要掌握
- 数据通路五段：PC → 指令存储器 → 译码 → 寄存器堆 → ALU → 数据存储器 → 写回
- 控制信号：每条指令对应一组控制位；控制器本质是"指令 → 控制位"的查表
- Nand2Tetris Project 5：Hack CPU（ALU + A/D 寄存器 + PC + 控制逻辑）→ 整机 Computer
- 用 TypeScript 写周期级 CPU 模拟器：把每个时钟沿的状态更新规则写对
- 五级流水线（IF / ID / EX / MEM / WB）：吞吐与延迟的区别、加速比怎么算
- 三类冒险：结构冒险、数据冒险（RAW、load-use）、控制冒险；对策：转发 forwarding、停顿 stall、分支预测（先学静态）
- cache 全套：直接映射 / 组相联 / 全相联；地址划分 tag–index–offset；命中与缺失；LRU 替换；写策略 write-through vs write-back、write-allocate vs no-allocate；脏位的作用
- 性能计算：AMAT = 命中时间 + 缺失率 × 缺失代价；考虑 cache 的 CPI 计算
- 虚拟存储与 TLB、中断与 DMA（概念级，等级 5 项目里可深化）

### 常见错误
- 冒险只背名词：说不清为什么 forwarding 解决不了 load-use（数据在 MEM 段末尾才出来，下一条指令 EX 段就要用）
- cache 题目算错位数：块大小、相联度、容量对 tag / index / offset 划分的影响没有一步步推
- 混淆 write-back 和 write-through 的适用场景，忘了脏位是 write-back 的配套机制
- 写 CPU 模拟器时同一周期"先写后读"——寄存器堆应该读旧值、写新值，更新顺序错了整个程序行为都错（模拟器 bug 的最大来源）
- 模拟器"跑得像就行"，不用测试向量验证每个时钟沿的状态——隐性 bug 埋到后面爆炸
- 流水线题不画时空图，靠脑补对齐指令

### 练习（代码放 `04_CPU与存储/`）
- [ ] Nand2Tetris Project 5：CPU.hdl + Computer.hdl，官方测试全绿
- [ ] ex: TypeScript 版 Hack CPU 模拟器：加载等级 3 汇编器输出的 .hack 文件，支持单步、断点、寄存器 / 内存观察；用官方 ROM 测试 + 自己的汇编程序双重验证
- [ ] ex: 可配置 cache 模拟器：输入地址 trace，输出命中率；容量、块大小、相联度、写策略全部可配，同一 trace 横向对比不同组织
- [ ] ex: 给 CPU 模拟器加五级流水线 + forwarding + 静态分支预测，统计 CPI，与单周期版对比算加速比
- [ ] 手算题（NOTES.md）：cache 地址划分、AMAT、流水线时空图各若干题

### 晋级标准
- [ ] 全链路闭环：自己写的汇编程序 → 自己的汇编器 → 自己的 CPU 模拟器，一路跑通
- [ ] cache 模拟器输出与手工推算一致，并能解释同一 trace 在不同组织下命中率差异的原因

## 等级 5：独立项目——造一台"自己的计算机"（约 1–2 个月）

**核心认知：独立做项目 = 定义规格 + 分层实现 + 用测试证明正确 + 用数据说话。一台完整的"你的计算机" = ISA 文档 + 汇编器 + 模拟器 + 测试套件 + 性能报告。编码只占一半，另一半是"证明它对"。**

### 需要掌握
- 规格先行：先写 ISA 文档（指令编码表、寄存器约定、内存模型），再动第一行代码
- 分层与模块化：汇编器 / 模拟器内核 / cache / CLI 各自成模块，接口先定好
- 测试策略：单元测试（逐条指令、逐个 cache 行为）+ 端到端测试（完整程序对比预期输出）+ 与已知正确实现对拍
- 性能分析：CPI 分解、cache 命中率报告、加速比——用数据支撑设计结论
- 版本管理与文档：git 提交粒度、README 写给使用者、ISA 文档写给"未来的自己"

### 常见错误
- 不写规格直接开码，模拟器改到第 8 天发现指令编码定得不合理，全部返工
- 没有测试对拍，"应该对了吧"式开发，后期每个 bug 都要全局排查
- 一次性想实现整本 ISA 手册——范围失控，烂尾
- 性能结论没有数据：说"加了 cache 快了"，快了多少、命中率多少，一问三不知
- 文档留到最后一天补——补不出来，等于没有

### 毕业项目（选一个完整交付，代码放 `05_毕业项目/`）
- [ ] 方向 A · RISC-V 工具链：TS 写 RV32I 子集汇编器 + 周期级五级流水线模拟器 + 简化 cache，能跑 godbolt 上 riscv-gcc 编译出的真实小程序，输出性能报告（CPI 分解、cache 命中率、与无 cache 版对比）
- [ ] 方向 B · 可视化计算机：把等级 4 的模拟器搬到浏览器（TS + 网页），单步执行、寄存器 / 内存 / 流水线动画，做成能给别人讲课的教学工具——TypeScript 前端技能直接复用
- [ ] 方向 C · 性能分析报告：用 C 写矩阵乘法 / 转置的朴素版与分块优化版，配自己的 cache 模拟器解释性能差异，写成有数据支撑的分析报告
- [ ] 硬性要求（无论哪个方向）：ISA 或架构文档、单元 + 端到端测试、README 让别人能跑起来、至少一组性能数据表

### 毕业标准（"能独立做项目"的定义）
- [ ] 从零定义规格并实现，不照抄教程代码（查资料、看参考实现的思路可以）

- [ ] 设计取舍说得出理由：为什么选这个指令子集、为什么这样切模块、不用它会怎样
- [ ] 有完整交付物：别人照着 README 能跑起来，并复现你的性能数据

## 路线设计说明

- 主线选 Nand2Tetris：它把"从与非门到 CPU"切成了带官方测试脚本的六个 project，自学不用自己发明练习和判分标准
- 电路层与模拟器层两条腿走路：等级 2、4 的 HDL 让你懂"机器为什么能造出来"，等级 3–5 的 TS 模拟器让你懂"机器如何精确建模"——只走一条腿会瘸
- 等级 1 的练习用 TS 写而不是纯手算：写转换器 / 解码器的过程会暴露理解漏洞，比刷题狠，顺便巩固 TypeScript
- 保留手算题：cache 划分、AMAT、流水线时空图是面试与考研的硬通货，也是看懂自己模拟器输出的前提
- 每级刻意衔接：等级 1 的补码 → 等级 2 ALU 的控制位；等级 3 汇编器的输出 → 等级 4 CPU 模拟器的输入；等级 4 的模拟器 → 等级 5 项目的底座——前面每一级都在给后面造零件
- 每一级的晋级标准都是"能做到什么"，不是"看过什么"——卡在某一级，比带着窟窿往前走快
