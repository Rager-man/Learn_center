## 第 2 课记录

**踩坑与事件（均已修）**：

- **id 复活复用 bug**：add 从"数组尾部 id+1"推导，删除尾部联系人后再 add 会拿到用过的 id（实测反例：Alice=1,Bob=2 → remove(2) → David 又拿到 2）。学生自修为 `let nextId = 1` + `id: nextId++`。建模教训已讲：id 必须单调递增，不能从当前数据推导。
- **属性简写把"缺席"变"显式 undefined"**：`{ phone }` 在未传时打出 `phone: undefined`（字段存在）。学生自修为条件展开 `...(phone === undefined ? {} : { phone })`，修复后字段整个缺席。
- 演示区漏 update 调用 → 学生补上；3 处装饰清理（草稿死注释 / 实验残留 / 双打印）两轮未动 → **导师代清**。此后装饰性清理一律导师直接代劳，不占来回。

**亮点**：

- update 参数 `Partial<Omit<Contact, 'id' | 'tags'>>`——超前用第 7 课武器，Omit 掉 id 是正确建模判断（展开口述未验证，第 7 课回炉 Contact 时补验）。
- `nextId++` 后缀自增、`if (contact)` 真值窄化——均无师自通（后者是第 3 课招式，判卷时已点破）。
- 实验 1 的"镜子"照出 update 走 Object.assign 直接改属性；已顺带补充：Object.assign 签名不做 readonly 检查（拦截盲区，深讲留第 7 课）。

**教学观察（第 3 课要用）**：

- **整改指令必须原子化**：一次 5 项清单学生只修了显眼 2 项；第二轮给到"行号 + 改法代码"手把手级后修完。以后整改清单带行号带代码。
