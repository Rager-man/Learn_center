# TypeScript 开发 20 小时速通计划

> 目标：用 10 次 × 2 小时，掌握 TypeScript 开发最重要的 20%——**全程 strict、不开 any**，独立写出多文件命令行工具，并交付一个带校验和测试的 mini 项目。
> 前置要求：Python 基础（函数、列表、字典、pip 即可），JS/TS 零基础。路上遇到没见过的 JS 语法，去[现代 JavaScript 教程](https://zh.javascript.info)查对应章节，或直接问 AI 导师——别顺藤摸瓜把整本 JS 教程读完。
> 与 [00_学习路线图.md](00_学习路线图.md) 的关系：那份是 4–6 个月的完整路线，本计划是它的浓缩核心——覆盖等级 1–2 的全部、等级 3 的核心、等级 4 的最小实操、等级 5 做迷你版。20 小时后想深入，从长期路线的等级 3 接着走。

## 怎么用这份计划

- **每次的节奏**：约 30 分钟学（读学前阅读）→ 80 分钟练（写代码）→ 10 分钟复盘。
- **复盘的正确姿势**：合上代码，先凭记忆把复盘问题的答案**口述或写下来**，再打开验证。"感觉我知道"不算数——能说出来才是真的会。
- **建议隔天一次**，3–4 周完成。间隔重复比连续突击记得牢得多。
- **卡住超过 20 分钟**就求助：把你期望什么、实际发生什么、完整报错贴给 AI 导师（也就是我），别自己耗着。
- 练习做不完就压缩范围，**但复盘不能跳过**。
- 完成一项练习就把 `[ ]` 勾成 `[x]`。
- 两条底线贯穿全程：**`npx tsx` 直跑不碰构建；strict 下 0 error、不写 any**（`unknown` + 守卫/zod 是唯一逃生门）。

## 最重要的 20% 是什么

TypeScript 的类型系统深不见底——类型体操、条件类型、装饰器、元编程……但日常开发里真正天天用的就那么几样。以下 8 项就是那关键的 20%：

| #   | 核心内容                                   | 为什么重要                                       |
| --- | -------------------------------------- | --------------------------------------------- |
| 1   | 类型擦除 + strict 模式                       | 地基认知。不懂"类型管不到运行时"，你会一直疑惑"编译器明明说没问题，跑起来为什么还是炸了" |
| 2   | 类型建模：interface / type、联合、字面量、`as const` | 类型的真正价值是逼你写代码之前把数据的形状想清楚                    |
| 3   | 窄化（narrowing）                          | 日常写 TS 用得最多的机制，strict 下它无处不在                 |
| 4   | 判别联合 + `never` 穷尽检查                    | 用类型建模业务状态的核心武器，让非法状态不可表示                     |
| 5   | 边界校验：`unknown`、类型守卫、zod                | 类型安全的第一道防线在数据**进来**的地方，不在代码中间                |
| 6   | 异步：Promise、async/await、all/allSettled  | JS/TS 的主旋律；忘 await 是新手第一大坑                    |
| 7   | 泛型与工具类型（读 + 写基础）                       | 看懂流行库的类型签名、写出可复用代码的门槛                        |
| 8   | 最小工程化：npm、ESM 多文件、vitest              | 从"一个脚本"到"一个项目"的跨越                           |

### 明确砍掉的 80%（20 小时内不碰）

- **类与继承等 OOP 体系**：现代 TS 项目函数优先，类不是主角；`implements` 遇到再查
- **enum**：坑比好处多，直接学 `as const` 对象替代——很多团队规范也是这么写的
- **类型体操**：`infer` 深入、模板字面量类型、复杂条件类型——三行逻辑不配二十行类型，先会读再谈写
- **构建与打包**：tsc 产物配置、tsup、tsconfig 全家桶——全程 `npx tsx` 直跑，第一天就被工具链劝退不值得
- **ESLint / Prettier / `.d.ts` 编写**：质量工具是"代码写对了"之后的事
- **React / hono / express 等框架**：语言没扎实前上框架，你分不清报错来自哪一层
- **JS 深水区**：原型链、闭包原理、生成器、Symbol——遇到再查，不占用这 20 小时

这些不是不学，是现在不学——长期路线图（[00_学习路线图.md](00_学习路线图.md)）里都有安排。

## 10 次课

### 第 1 次 · 跑起来 + 第一个认知：类型会被擦除

> **核心认知：TypeScript = JavaScript + 编译期类型检查。类型在编译后被完全擦除，管不到运行时。**

- 代码放：`01_语法起步/`（上课时创建，顺便 `npm init -y` + `npm i -D typescript tsx @types/node`）
- 学前阅读（约 30 分钟）：[官方 Handbook](https://www.typescriptlang.org/docs/handbook/intro.html) 的 "The Basics" 与 "Everyday Types" 前半章；英文吃力就看[阮一峰 TypeScript 教程](https://wangdoc.com/typescript/)的对应章节，或让 AI 导师 10 分钟讲一遍

**学习目标**
- 装好环境，两种方式跑 TS：`npx tsx` 直跑（日常用）vs `tsc` 编译（看产物用）
- 分清类型注解 vs 类型推断：函数边界必须写，函数体内让编译器推
- 会用原始类型、联合类型 `string | number`、字面量类型 `"small" | "large"`
- 建立"类型擦除"认知：编译器说没问题 ≠ 运行时不会炸

**练习任务（80 分钟）**
- [x] （15 分钟）报错观察：写 5 个变量故意错赋值，逐条读报错；再删掉注解，用编辑器悬停看推断结果——感受"推断在干活"
- [x] （35 分钟）BMI 计算器：身高体重 → BMI → 分级；分级结果用字面量联合 `"偏瘦" | "正常" | "偏胖" | "肥胖"`；输入来自 `process.argv`，体会 `string` → `number` 的转换（`Number()` 失败得 NaN，得处理）
- [x] （30 分钟）类型擦除实验：写一个带完整注解的文件，用 `npx tsc --strict --outDir tmp --ignoreConfig 文件名.ts` 编译，打开产物 `.js` 看类型去哪了；再写 `const data: { name: string } = JSON.parse('{"nama": "typo"}')`——类型明明说有 `name`，跑起来打印 `undefined`，解释为什么

**复盘问题**
1. 不看代码，说出"类型擦除"：类型在什么时候、去哪了？它为什么管不到运行时？
2. `JSON.parse` 的返回值类型是什么？为什么直接把它的结果当安全数据用是错的？
3. 类型注解什么时候必须写、什么时候该省？你的判断标准是什么？

### 第 2 次 · 用类型建模数据——写代码之前先画图纸

> **核心认知：类型的真正价值不是"编译器不报错"，而是逼你在写代码之前把数据的形状想清楚。**

- 代码放：`01_语法起步/`
- 学前阅读（约 30 分钟）：[Handbook](https://www.typescriptlang.org/docs/handbook/intro.html) "Everyday Types" 的对象、数组、函数参数与返回值部分；顺带把[现代 JavaScript 教程](https://zh.javascript.info)的数组方法（map/filter/find）扫一遍——Python 列表推导在这里的对应物

**学习目标**
- 用 `interface` / `type` 描述对象，知道两者取舍（多数场景随意选、团队统一即可；需要联合或交并集时只能 `type`）
- 可选属性 `?`、只读 `readonly`；访问可选属性得到的是 `T | undefined`
- 数组 `Contact[]`、元组 `[string, number]`、`as const`
- 给函数写完整的参数与返回值类型——每个函数都是一个类型边界

**练习任务（80 分钟）**
- [x] （60 分钟）内存通讯录：`Contact` 含 id / 姓名 / 电话（可选）/ 标签数组；实现 `add` / `remove` / `update` / `findByTag` 四个函数，每个都有完整类型注解，strict 下 0 error
- [x] （20 分钟）改造实验：把电话标成 `readonly`，试着改它——看编译器拦不拦；用 `as const` 定义"合法标签"常量数组，让标签参数的类型只能是其中之一

**复盘问题**
1. `interface` 和 `type` 你会怎么选？说得出一条自己的规则。
2. 可选属性 `phone?: string`，访问 `contact.phone` 时拿到的是什么类型？这为下一次课埋了什么伏笔？
3. 你的通讯录里，哪个函数的返回类型最难写？为什么？

### 第 3 次 · 可空与窄化——日常用得最多的机制

> **核心认知：strict 下满屏的 null/undefined 报错不是找麻烦，是编译器在指出"这里可能没值"。窄化（narrowing）就是你逐个回应它的过程。**

- 代码放：`02_类型建模/`（上课时创建）
- 学前阅读（约 30 分钟）：[Handbook](https://www.typescriptlang.org/docs/handbook/intro.html) 的 "Narrowing" 章——全 Handbook 性价比最高的一章，读两遍都值

**学习目标**
- 掌握空值工具：可选链 `?.`、空值合并 `??`（注意 `??` 和 `||` 对 `0` / `""` 的区别）
- 窄化的全部日常手段：`typeof`、`in`、`instanceof`、真值窄化
- 知道 `Map.get()` / `Array.find()` 返回 `T | undefined`，必须先窄化再用
- 树立纪律：`as` 和 `!` 是逃生舱不是日常工具——本次练习全程禁用

**练习任务（80 分钟）**
- [x] （40 分钟）修复"满屏红"：让 AI 导师生成（或自己翻出）一段约 30 行、到处直接 `.xxx` 访问可空值的烂代码，不用 `as` 和 `!`，用窄化 + `?.` / `??` 修到 0 error
- [x] （40 分钟）猜数字命令行游戏：随机数 + 循环读输入；输入解析失败（NaN）要窄化处理，猜中后打印用了几轮——把第 1 次 BMI 的输入转换坑正式补完

**复盘问题**
1. `contact.phone?.length ?? 0` 这行代码，两个运算符分别在处理什么？
2. `??` 和 `||` 有什么区别？举一个用 `||` 会出 bug 的具体例子。
3. 什么情况下才"允许"用 `!`？你现在的答案和第 1 次相比有变化吗？

### 第 4 次 · 判别联合——让非法状态不可表示

> **核心认知：一堆 boolean 字段（isPaid + isShipped + isCancelled）组合出大量非法状态；判别联合让非法组合在编译期就不存在。**

- 代码放：`02_类型建模/`
- 学前阅读（约 30 分钟）：[Handbook](https://www.typescriptlang.org/docs/handbook/intro.html) "Narrowing" 章的 discriminated union 部分；再让 AI 导师讲清 `unknown` vs `any`——一句话：unknown 是"我还不知道"，any 是"我放弃了"

**学习目标**
- 用判别联合建模业务状态：`{ status: "pending" } | { status: "paid"; paidAt: string } | ...`
- `switch` + `never` 穷尽检查：新增状态时，漏处理的分支编译报错
- 面对未知数据的第一反应是写类型守卫，不是 `as any`
- 会写自定义类型守卫 `function isFoo(x: unknown): x is Foo`

**练习任务（80 分钟）**
- [x] （45 分钟）订单状态机：`pending → paid → shipped | cancelled`，每个状态带自己独有的字段；写 `next(order)` 做合法流转 + `switch` 穷尽检查；然后故意删掉一个 case，看编译器怎么骂你——把报错截图存下来
- [x] （35 分钟）手写解析器：`JSON.parse` 一个 `unknown`，用 `typeof` / `in` 逐层守卫成 `Order` 类型；全程禁止 `as`；写 3 组坏数据验证守卫能拦住

**复盘问题**
1. 判别联合比 `isPaid` + `isShipped` + `isCancelled` 三个 boolean 好在哪？后者能表达出多少种非法状态？
2. `never` 穷尽检查是怎么工作的？为什么新增状态时它会强制你处理？
3. "边界用 unknown，核心永不 any"——这句话你怎么理解？

### 第 5 次 · 异步——JS/TS 的主旋律

> **核心认知：async 函数返回的永远是 Promise。忘了 await，你拿到的是"提货单"而不是货。**

- 代码放：`03_工程与异步/`（上课时创建）
- 学前阅读（约 30 分钟）：[MDN：Promise](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Promise) + [MDN：使用 Promise](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Using_promises)；写过 Python `asyncio` 的话，经验可以直接平移，只是换了个语法壳

**学习目标**
- 理解 Promise：一个"未来才有值"的容器；`await` 是把值取出来
- `async` / `await` + `try/catch` 处理异步错误，错误路径必须有人接
- `Promise.all`（一个失败全失败）vs `Promise.allSettled`（各自结算）——什么时候用哪个
- 体感记住：串行 await 与并发 all 的耗时差异

**练习任务（80 分钟）**
- [ ] （20 分钟）忘 await 实验：`const user = fetchUser()` 不 await，直接 `user.name`——看报错或打出什么；对照 await 版本
- [ ] （30 分钟）串行 vs 并发：写 `sleep(ms)`（`setTimeout` 包装成 Promise），三个"任务"分别串行 await 与 `Promise.all` 并发，各计时总耗时——并发版本应接近最慢任务耗时，而非三者之和
- [ ] （30 分钟）重试函数：`retry(fn, times)` 失败重试最多 N 次，用随机失败的任务（`Math.random() < 0.5` 就抛错）测试；最后用 `allSettled` 跑 5 个任务，输出成功/失败报告

**复盘问题**
1. 忘了 `await` 会发生什么？为什么 TypeScript 有时报错、有时不报？
2. `Promise.all` 和 `allSettled` 各自适用什么场景？"抓取 10 个网页，单个失败不中断"该用哪个？
3. `async` 函数里 `throw` 出去的错误，谁接得住？没人接会发生什么？

### 第 6 次 · 边界校验——fetch、JSON 与 zod

> **核心认知：类型只管编译期。数据进来的边界（网络、文件、用户输入）必须做一次运行时校验，之后才能全程类型安全。**

- 代码放：`03_工程与异步/`
- 学前阅读（约 30 分钟）：[MDN：使用 Fetch API](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API/Using_Fetch)（重点：fetch 不会因 404/500 reject，必须查 `res.ok`）+ [zod 官网](https://zod.dev/)的 "Basic usage" 部分

**学习目标**
- fetch 的三条错误路径分开处理：网络错误（reject）、非 2xx（`res.ok`）、JSON 损坏（`json()` 抛错）
- 用 zod 在边界校验一次：定义 schema → `safeParse` → `z.infer` 推导类型
- 意识到命令行参数、环境变量、文件内容同样是边界
- 知道 zod 替你做了什么：它就是第 4 次手写守卫的自动化版

**练习任务（80 分钟）**
- [ ] （60 分钟）天气 CLI：调 [open-meteo](https://open-meteo.com/en/docs)（免注册），命令行传城市经纬度，输出今明温度；zod 校验 API 返回；三条错误路径都要处理（断网、改坏 URL、结构变了——把 schema 里某字段名改错即可模拟）
- [ ] （20 分钟）边界清单：数一数这个 CLI 一共有几个"数据进口"（argv、API 响应……），每个进口都有校验吗？没补上

**复盘问题**
1. fetch 的三条错误路径分别是什么？各自怎么处理？
2. 用了 zod 之后，类型从哪来？和手写 interface 比有什么本质优势？
3. "边界校验一次，之后全程类型安全"——这句话里的"一次"和"之后"分别指什么？

### 第 7 次 · 泛型与工具类型——类型层面的函数

> **核心认知：泛型是"类型的参数"。你不需要成为类型体操选手，但必须读得懂 `Array<T>`、写得出简单泛型函数。**

- 代码放：`04_进阶与质量/`（上课时创建）
- 学前阅读（约 30 分钟）：[Handbook](https://www.typescriptlang.org/docs/handbook/intro.html) 的 "Generics" 章（读到 generic constraints 为止）；工具类型 `Partial` / `Pick` / `Omit` / `Record` 的文档部分

**学习目标**
- 看懂泛型：`Array<string>`、`Promise<User>`、`Record<string, T>`——把 `<T>` 想成函数的参数
- 写简单泛型函数 + 约束：`<T, K extends keyof T>`
- 会用工具类型 `Partial` / `Pick` / `Omit` / `Record` / `ReturnType` 消灭重复类型
- 知道什么时候**不该**抽泛型：只有一个调用方时，具体类型比泛型好

**练习任务（80 分钟）**
- [ ] （50 分钟）泛型小工具三连：`groupBy<T>(items, keyFn)`、`pluck<T, K extends keyof T>(objs, key)`、`chunk<T>(arr, n)`——签名自己推，写完用编辑器悬停验证推断类型（`pluck(contacts, "name")` 应得到 `string[]`）
- [ ] （30 分钟）回炉改造：给第 2 次的 `Contact` 的 update 参数换成 `Partial<Pick<Contact, "name" | "phone">>`；再定义 `Record<Tag, number>` 做标签计数——体会"类型也可以复用"

**复盘问题**
1. `pluck<T, K extends keyof T>(objs: T[], key: K): T[K][]`——逐段说出这个签名每个部分在承诺什么。
2. `Partial<Contact>` 展开是什么？它解决了 update 函数的什么麻烦？
3. 什么时候不该抽泛型？你的判断标准是什么？
