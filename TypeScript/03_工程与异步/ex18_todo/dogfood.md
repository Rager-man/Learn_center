| # | 命令 | 发生了什么（原样记，别美化） |
|---|------|------------------------------|
| 1 | `npm run todo -- add 买牛奶` | `已添加 #1 买牛奶`（exit 0） |
| 2 | `npm run todo -- add 写周报` | `已添加 #2 写周报`（exit 0） |
| 3 | `npm run todo -- add ` （空标题） | `标题为空，不符合要求`（exit 1） |
| 4 | `npm run todo -- list` | `[ ] # 1 买牛奶`<br>`[ ] # 2 写周报`（exit 0；`#` 和数字之间多打了个空格，是 `# ${task.id}` 写的） |
| 5 | `npm run todo -- doing 1` | `待办列表已更新`（exit 0；没说更新了谁、更新成什么） |
| 6 | `npm run todo -- done 1` | `待办列表已更新`（exit 0）；随后 `list` 看到 `[x] # 1 买牛奶 (完成于 2026-0)`——时间戳只剩 `2026-0` |
| 7 | `npm run todo -- doing 1` （已 done 再开始） | `任务 1 当前是 done，不能开始`（exit 1，人话 ✓，model 的 throw 被 cli 接住了） |
| 8 | `npm run todo -- done 99` （不存在的 id） | `未找到对应任务id`（exit 1） |
| 9 | `npm run todo -- ` （无参数） | `todo <add|list|doing|done> [参数]`（exit 1） |
| 10 | ⑧ Ctrl+C 实验：`npm run todo -- add ` 慢慢打字打到一半按 Ctrl+C，再 `list` —— 数据还在吗？ | 两个层面都验了：① 打字打到一半按 Ctrl+C——参数还在 shell 手里，程序压根没启动，数据当然原样；② 更狠的实测：启动 `add 打断实验` 后 0.2 秒 `kill -INT`，进程 exit 130 死掉，这一条**没入库**，再 `list`——#1、#2 原样，文件没坏。原因：读→改→**一次性全量写**，打断落在写之前，要么整条不写（旧文件完好），要么已写完 |
| 11 | ⑨ 改坏实验：打开 todo.json 手动删一个引号保存，再 `npm run todo -- list` —— 兜底活了吗？`.bad` 文件在吗？打开看一眼坏现场 | 删掉 `"买牛奶"` 的闭引号再 `list`，输出：`数据文件坏了，原样备份到 todo.json.bad，从空库重新开始` + `暂无任务`——**兜底活了，没裸崩** ✓；`.bad` 在，打开就是坏现场（`"title": "买牛奶,` 那行缺引号原样躺着）；todo.json 被 rename 走，之后 `add` 会从空库重建；注意空库 `list` 的退出码是 1（见别扭瞬间 3） |
| 12 | `npm run todo -- doing abc` （自选：非数字 id） | `未找到对应任务id`（exit 1）——`abc` 经 `Number()` 变 NaN，落进"找不到"分支：其实不是"没有这个 id"，是"id 根本不是数字"，报错误导 |

## 3 个失败或别扭的瞬间（本任务的交付物）

| # | 现场命令 | 现象 | 根因在哪层（猜） | 怎么改 |
|---|----------|------|------------------|--------|
| 1 | npm run todo -- add | 标题为空，无法加入待办列表 | 边界校验 | 空标题也可以加入到待办列表，并支持修改标题|
| 2 | npm run todo -- doing 1（done 1 同理）后 list | `(完成于 2026-0)`——时间戳只剩年+一个数字，月日时分全丢；todo.json 里存的就是 `"finishedAt": "2026-0"` | 黑盒照抄抄错了：model.ts 的 `now()` 把 `slice(0, 16)` 写成 `slice(0, 6)`；类型系统管不住运行时的字符串截取——截几位它都是 string | model.ts 的 `now()` 改回 `slice(0, 16)` |
| 3 | 改坏兜底后（空库）npm run todo -- list | 打印 `暂无任务` 但 shell 退出码是 1——"看一眼空列表"被当成了错误，脚本里串用会被误判失败 | 错误处理：cli.ts 的 list 分支把"正常空态"和"真正的错误"塞进了同一条 `process.exit(1)` | 打印"暂无任务"后 `break`（exit 0），退出码 1 只留给真错误 |
