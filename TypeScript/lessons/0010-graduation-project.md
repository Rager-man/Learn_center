## §1 核心认知：2 小时交付 > 2 个月"学完"

> ◆ **本课唯一必须带走的东西**
>
> **能用 2 小时独立交付一个完整小工具，比花 2 个月"学完"整个类型系统更有说服力。**

毕业考的不是新知识，是**组装的手感**：拿到一个需求，你知道先问"数据从哪进来"，知道合同先于代码、错误路径先于 happy path、测试盯着纯函数。这些 reflex 前 9 课各练了一块，今天一次验货。三个推论，今天反复用：

1. **复用是本事，不是作弊。** 前九课的代码是你自己写、自己测、自己修过的——毕业项目把它们搬进新家，是工程师的日常（造轮子才是新手的虚荣）。唯一的纪律是丑话②：搬运要整段、要注明出处，不许斜着 import。
2. **交付 = 代码 + 测试 + README，三件缺一不可。** 只有代码叫"能跑"，加上测试叫"敢改"，再加 README 才叫"交付"——硬性要求第 4 条为什么和第 1 条平起平坐，今天做完你就懂了。
3. **边界意识毕业考。** 空输入、断网、非 2xx、坏数据——四条错误路径**每条都要有人话**。第 6 课你给天气 CLI 数过进口，今天没人替你数了：进口在哪、谁守门、门破了怎么办，全是你说了算——也全是你负责。

> ⚠️ **本课避坑**
> **别把 2 小时的活定成 2 天的。** 任务 0 的 5 行需求就是干这个的：范围定小、定死，先让四条硬性要求全过，再谈锦上添花。纪律延续：全程禁 `as` / `!`，命名 camelCase——最后一天了，别破功。

### §1.1 动笔预测（5 分钟）

老规矩，**先别用 IDE**。A、B、C 是问下场；D 是纸面审计。（A、B、C 的现场都是我备课实测的——2026-09-15，GitHub 真身。）

```typescript
// A —— 拿到响应直接用
const res = await fetch("https://api.github.com/users/octocat/repos");
const repos: Repo[] = await res.json();   // Repo = { name: string; language: string; pushed_at: string }
// ← tsc 报不报？

// B —— 用户名不存在（比如敲错成 octocatt），fetch 本身 reject 吗？
// ← 不查 res.ok、直接 res.json()，接下来会发生什么？

// C —— 合同写 z.object({ name: z.string(), language: z.string(), ... })，
//   octocat 的真实数据（8 个仓库）喂进 safeParse，什么下场？

// D —— 纸面审计：AI_agent 第 1 课 ex1 的开头三行是
//   const BASE_URL = process.env.LLM_BASE_URL!;
//   const API_KEY  = process.env.LLM_API_KEY!;
//   const MODEL    = process.env.LLM_MODEL!;
//   加上后面的 const data = await resp.json(); 和 data.choices[0].message.content——
//   按这门课的纪律，一共几处违规？各该怎么改？
```

写完再对照（猜错很正常，错在哪就是哪没懂；A、B、C 建议开工后亲手再遇一次）：

> [!success]- 对照答案（先写完再展开）
> **A：不报，一片沉默。** `res.json()` 的返回类型是 `Promise<any>`——await 完还是 any，赋给谁都不拦（备课实测：放进项目里 `tsc --noEmit` 照样沉默）。这是 any 逃生门在这门课的**最后一次现身**：第 1 课你见过它放行 `data.nama`，今天它放行的是"响应冒充仓库列表"。锁只有一把：进门处 safeParse。
>
> **B：fetch 不 reject，错误对象冒充数据进门。** 实测：404 时 fetch 正常 resolve（`status=404, ok=false`），`res.json()` 也正常解析——body 是一段**合法 JSON**：`{"message":"Not Found","documentation_url":"...","status":"404"}`。语法层没病，病在语义层：它是错误消息，不是仓库列表。你若写了 `z.array(...)` 合同，safeParse 会拦下它（实测原文：`Invalid input: expected array, received object`）——但"用户名不存在"这句人话只能从 `res.ok` 分支来。**fetch 只管"送到对面没有"，HTTP 状态码是对面给你的业务信号**——第 6 课三条错误路径的第 2 条，最后一次上岗。
>
> **C：5 个仓库当场被拦。** 实测：octocat 名下 8 个仓库，**5 个的 `language` 是 `null`**（没检测出主语言的仓库就这样）。合同写 `z.string()`，safeParse 拦下，原文：`language: Invalid input: expected string, received null`——报错说的是人话，但方向错了：**不是数据坏，是你的合同撒谎**（声称 language 必有，事实是可为空）。修法一行：`z.string().nullable()`——合同如实刻画世界，把 null 翻译成"未标注"是 core 的活，不是 schema 的活。
>
> **D：至少 5 处。** 三个 `!`（赌环境变量在——`!` 是"我赌它在"，这门课的替代是"我查过它在"：窄化/校验后缺谁报谁的名）；`resp.json()` 的 any + `data.choices[0].message.content` 全程 any 路径（没人验过响应长什么样）；没查 `resp.ok`（非 2xx 会怎样？）；没重试（网络抖一下就死）。**选 B 的毕业项目，就是把这些一处一处修掉**——AI_agent 课教你"调得通"，这门课教你"调得稳"。

### §2.3 选项 A 地形：GitHub REST API

- **端点**（骨架 api.ts 黑盒区已给）：`GET /users/{username}/repos?per_page=100`，带 `Accept: application/vnd.github+json`。
- **字段形状**（备课实测 octocat，2026-09-15）：`name`（string）、`language`（**string 或 null**——C 段的案发现场）、`pushed_at`（ISO 时间串，字典序 = 时间序）、`html_url`（string）。合同照这四个收，别贪多。
- **免 token 的代价**：每 IP 每小时 60 次。超了是 403——人话写"限额了，一小时后再试或配 token（学有余力①）"。测试**不碰网络**（vitest 里发真请求又慢又不稳），60 次的命留给验收流水。
- **报告三件**（速通计划定的最小集）：仓库总数 / 最近推送（`pushed_at` 最大的那条）/ 语言分布（null 计入"未标注"）。fork 的仓库算不算？>100 仓库的用户怎么办？——**这是你的项目，边界你自己定**，定了就写进 README 的"已知局限"，这是最体面的收法。
- **并发**（速通计划原文"并发拉取"）：一个用户一次请求全拿完（per_page=100），用不上并发；真想练，学有余力②给你留了"全仓库语言字节统计"的真并发题。

### §2.4 选项 B 地形：AI 调用加固器

- **对面**：AI_agent 第 1 课 ex1 的调用骨架（骨架 api.ts 黑盒区已给，含 `AbortSignal.timeout(60_000)` 照抄）。环境变量三兄弟 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 在 shell 里 export 过——**注意 `process.env.X` 的类型是 `string | undefined`**，D 段审掉的三个 `!` 就是指这里的合法替代：校验 + 缺谁报谁的名。
- **两份合同**：① 响应壳（只要 `choices[0].message.content` 是 string）；② 结构化输出（content 里那坨 JSON 必须长成你的 `Card`——字段按你的 5 行需求定，骨架给的是三字段的生词卡草样）。
- **加固三连**（这个项目的本体）：调用处查 `resp.ok`（非 2xx 有人话）→ 响应壳过合同（any 不许进门）→ content 剥围栏 + `JSON.parse` + safeParse（ex18 parseDb 两层坏原样平移）。
- **重试兜底**：模型没按要求说话（parseCard 回 null）→ `withRetry` 把"重新问"来一轮（ex11 的 retry，泛型黑盒转正）。全败 → 人话 + exit 1，不裸崩。
- **两门课在这里正式打通**：AI_agent 课教的是"LLM 怎么调、消息怎么攒"；这门课问的是"**网络断了、key 错了、模型胡说了，你的代码还站得住吗**"。加固器 = 两问的交集。

- 💡 三条提示折叠在下面：

> [!tip]- 提示 1（选 A）：latest 别用 sort，用 reduce；空数组那格是考点
> `pushed_at` 是 ISO 串，字典序 = 时间序，`a.pushed_at > b.pushed_at` 直接比。8 个仓库找最大用 `reduce`（排整个数组是为 top1 付出的太多）；**空数组时 reduce 初值是 `undefined`**——这个分支（0 仓库的用户）测试必测清单 ③ 点名要摸到。

> [!tip]- 提示 2（通用）：今天若加数字参数，Number.isNaN 单独分支
> 比如 A 想加"只看前 N 名语言"、B 想让重试次数可配——`Number("abc")` 是 NaN 且**不报错**，直接拿去比较全都是 false，报错会指错方向。第 9 课 dogfood 你亲手踩过（`doing abc` 落进"未找到"分支）。修法：转换后 `Number.isNaN(n)` 单独分支，报"参数得是数字"。边界意识毕业考的加分位。

> [!tip]- 提示 3（选 B）：重试的是"整轮"，不是"解析"
> parseCard 回 null 后，重试必须是**重新调用 + 重新解析整轮**——模型上一次没按要求说话，重新读同一段话不会变出不同的结果。`withRetry(() => callLlm(prompt).then(parseCard))` 里 fn 是整轮；`null` 不是 throw，想触发重试得把"回 null"翻译成 throw 再让 withRetry 接（或者干脆自己写循环——两条路都合法，选一条说得出理由的）。

> ✅ **检查点（比写完代码更重要）**
> 空输入有人话 exit 1；正常路径完整输出 exit 0；断网、非 2xx（404/403 或 401/429）、坏数据、（选 B）env 缺失——每条路径实跑一次，人话 + 不裸崩；≥5 条 it 全绿、出生占位已删；`npx tsc --noEmit` 沉默；骨架里没选的那半照抄块删干净；每个文件各归各位（§0 归位表）；全程没写 `as` / `!`，命名 camelCase。

自测五题（每题先默答，再点开「看答案」）：

**Q1. `await res.json()` 的类型是什么？为什么 `const repos: Repo[] = await res.json()` 编译器不管？**

> [!question]- 看答案（先默答再点开）
> `Promise<any>`——await 完是 any。any 不是"任何类型都行"，是"**检查器下班了**"：赋给 `Repo[]` 当然放行，赋给任何东西都放行。A 段实测的沉默就是它。真正的锁在进门处：`res.json()` 的结果先当 `unknown` 摆着，safeParse 过了合同才升级成 `Repo[]`——"注解是声称，数据是事实"，这句话陪你到最后一课。

**Q2. 用户不存在（404）属于三条错误路径的哪一条？fetch 为什么不 reject？**

> [!question]- 看答案（先默答再点开）
> 第 2 条（非 2xx，查 `res.ok`）。fetch 的 reject 只管**网络层**（DNS 解析失败、连不上、超时 abort）——"请求送到了对面"它就功成身退；404 是对面**收到了、看懂了、明确回答"没有"**，这是业务层的正常回答，不是网络事故。所以 404 的 body 是合法 JSON（`{"message":"Not Found",...}`），语法层完全没病——不查 `res.ok`，错误消息就冒充数据进了门（B 段实测现场）。

**Q3. octocat 的 8 个仓库有 5 个 `language: null`——合同怎么写，才既不放走坏数据、也不误杀好数据？**

> [!question]- 看答案（先默答再点开）
> `language: z.string().nullable()`——**合同如实刻画世界**：事实是"多数仓库有语言、少数没有"，合同就写 `string | null`。写 `z.string()` 是让合同撒谎（C 段：5 个好仓库被拦）；图省事写 `z.any()` 是让合同下岗（什么都能进）。注意分层：null 翻译成"未标注"是 core 的 `??` 干的活——schema 只负责"是不是事实"，不负责"好不好看"。

**Q4. `process.env.LLM_API_KEY` 的类型是什么？AI_agent 课的 `!` 和这门课的替代方案，差在哪？**

> [!question]- 看答案（先默答再点开）
> `string | undefined`——环境变量可能在，也可能没人 export 过。`!` 是**非空断言**："我赌它在，编译器你别管"——赌赢无事发生，赌错运行时当场 TypeError（第 3 课起 as/! 禁令的原因）。替代方案是**把"赌"换成"查"**：if 窄化或校验函数，缺谁报谁的名（"环境变量 LLM_API_KEY 没设置"）+ 人话 exit——错误在进门处就被拦下，还带着下一步该干什么的说明。D 段审计的三个 `!`，修法全在这一句里。

**Q5. 把 ex18 的 parseDb 搬进今天的 core.ts，和第 8 课被点名的"测试 import 直插旧档案"，差在哪？**

> [!question]- 看答案（先默答再点开）
> 差在**代码住在哪、谁依赖谁**。搬运 = 把代码整段搬进新项目的文件、注明出处——它从此是毕业项目的一等公民，依赖方向清楚、测试测的就是交付的代码。直插 import = 旧档案还住在原地，新项目斜着够过去——旧档案的**顶层副作用**跟着进测试（第 8 课 npm test 打出演示输出的现形现场），仓库里从此多了一条横穿的依赖线。复用与抄近路的界线就这一条：**代码进没进自己的家**。
