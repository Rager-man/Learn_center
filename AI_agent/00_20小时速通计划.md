# AI Agent 开发 20 小时速通计划

> 目标：用 10 次 × 2 小时，掌握 AI agent 开发最重要的 20%——**脱离任何框架，手写出带错误处理的完整 agent**，并交付一个带护栏和评估集的迷你项目。
> 前置要求：TypeScript 基础（能读能写函数与 interface；并行 TS 课程进行中）+ 一个 OpenAI 兼容 API 的 key（智谱 GLM / DeepSeek / Qwen 均可）。
> 与 [00_学习路线图.md](00_学习路线图.md) 的关系：那份是 4–6 个月的完整路线，本计划是它的浓缩核心——覆盖等级 1–2 的全部、等级 3–4 各取最小实操、等级 5 做迷你版。20 小时后想深入，从长期路线的等级 3 接着走。

---

## 怎么用这份计划

- **每次的节奏**：约 30 分钟学（读学前阅读）→ 80 分钟练（写代码）→ 10 分钟复盘。
- **复盘的正确姿势**：合上代码，先凭记忆把复盘问题的答案**口述或写下来**，再打开验证。"感觉我知道"不算数——能说出来才是真的会。
- **建议隔天一次**，3–4 周完成。间隔重复比连续突击记得牢得多。
- **卡住超过 20 分钟**就求助：把你期望什么、实际发生什么、完整报错贴给 AI 导师（也就是我），别自己耗着。
- 练习做不完就压缩范围，**但复盘不能跳过**。
- 完成一项练习就把 `[ ]` 勾成 `[x]`。

---

## 最重要的 20% 是什么

AI agent 领域内容浩如烟海——框架十几个、论文每天出。但拆开看，每个 agent 的核心都是同一样东西。以下 7 项就是那关键的 20%：

| #   | 核心内容                        | 为什么重要                                         |
| --- | --------------------------- | --------------------------------------------- |
| 1   | LLM API 无状态本质 + messages 管理 | 地基认知。不懂"上下文是拼出来的"，后面全是空中楼阁                    |
| 2   | 结构化输出 + 解析兜底                | 可靠性的地基。模型输出永远不可全信                             |
| 3   | Function calling 完整往返       | agent 的心脏。模型只出参数，执行永远是你写的代码                   |
| 4   | 手写 agent loop（while 循环）     | 所有框架的核心就是这一个循环。脱离框架手写一遍，以后用框架才不被绑架            |
| 5   | 工具 schema 设计 + 错误回传         | agent 质量的真正来源。Anthropic 称之为 ACI，值得像投入 UI 一样投入 |
| 6   | RAG 最小 pipeline             | 给 agent 外接私有知识的标准方式                           |
| 7   | 护栏 + 最小评估集                  | 从"玩具"到"可用"的分界线                                |

外加一个生态认知：**MCP**（工具的开放标准），跑通一次即可。

### 明确砍掉的 80%（20 小时内不碰）

- **LangGraph / Agents SDK 等框架**：手写过循环之后，学任何框架只要一天；反过来则会被框架绑架
- **多 agent 编排**：90% 的场景一个 agent + 设计好的工具就够（Anthropic 官方观点）
- **向量数据库选型、混合检索、rerank**：入门用 numpy 余弦相似度就够，先懂原理再上工具
- **长期记忆系统、上下文压缩算法**：先学会"把上下文拼对"，再谈"把上下文压缩好"
- **微调、模型部署、前端界面、FastAPI 服务化、可观测性工具链**：都是"agent 本身写对了"之后的事
- **LangChain 全家桶**：抽象层太厚，恰恰遮住你现在最想看的东西

这些不是不学，是现在不学——长期路线图（[00_学习路线图.md](00_学习路线图.md)）里都有安排。

## 10 次课

### 第 1 次 · LLM API 的本质——无状态与对话历史

> **核心认知：API 是无状态的，每一轮对话都是你把历史拼起来重新发给它。**

- 代码放：`01_API基础/`
- 学前阅读（约 30 分钟）：你所用平台的 chat completion API 文档（智谱开放平台或 OpenAI 平台文档的对话接口部分），重点看 `messages` 参数结构

**学习目标**
- 建立"无状态、上下文是拼出来的"核心认知
- 认识 system / user / assistant 三种消息角色、token 与上下文窗口
- 不用任何框架，自己维护 `messages` 列表实现多轮对话

**练习任务（80 分钟）**
- [x] （40 分钟）最小调用：单轮问答，把完整响应结构打印出来，`choices`、`usage` 等每个字段都看一遍 ✅ 2026-09-02
- [x] （30 分钟）命令行多轮聊天机器人：自己拼 messages，支持 `/exit` 退出 ✅ 2026-09-02
- [x] （10 分钟）打印每次请求的 token 用量，感受"历史越长越贵" ✅ 2026-09-02

**复盘问题**
1. 不看代码，说出模型为什么"不记得"上一轮你说过的话？
2. 想删掉第 2 轮的对话，你会怎么改 messages？这对 token 消耗意味着什么？
3. system 和 user 消息的区别是什么？改动 system 内容，模型行为有什么变化？

---

### 第 2 次 · 结构化输出——让模型说"机器话"

> **核心认知：让模型输出给程序读的东西，永远要有兜底——模型输出不可全信。**

- 代码放：`01_API基础/`
- 学前阅读（约 30 分钟）：平台文档的 JSON mode / 结构化输出部分

**学习目标**
- 让模型稳定输出 JSON（`response_format` 或 prompt 约束两种方式都要试）
- 建立解析兜底的肌肉记忆：解析失败 → 重试/修复

**练习任务（80 分钟）**
- [ ] （60 分钟）评论分类器：输入商品评论，输出 `{"情感": "...", "类别": "...", "置信度": ...}`；故意输入乱码、空文本、超长文本，测试崩溃点
- [ ] （20 分钟）加兜底：JSON 解析失败时重试一次 + 把报错回传让模型修复

**复盘问题**
1. 列出你实测遇到的至少 3 种 JSON 输出失败方式，各自的兜底策略是什么？
2. 为什么说结构化输出是 agent 的地基——它和下一次要学的 tool calling 是什么关系？

---

### 第 3 次 · Function Calling——让模型驱动你的代码

> **核心认知：模型只输出"调用参数"，执行永远是你写的代码。**

- 代码放：`02_ToolUse/`
- 学前阅读（约 30 分钟）：[Anthropic: Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents) 前半部分 + 你所用平台的 function calling 文档

**学习目标**
- 完成一次完整的工具调用往返：定义 schema → 模型决策并给参数 → **你的代码执行** → 结果回传 → 模型总结
- 弄清 tool_calls 里模型给了你什么、没给你什么

**练习任务（80 分钟）**
- [ ] （50 分钟）给模型一个 `calculator` 工具，跑通单次"问数学题 → 调用 → 回答"
- [ ] （30 分钟）加一个 `get_current_time` 工具，观察模型如何在两个工具之间选择

**复盘问题**
1. 画出单次 tool call 的完整时序图：谁在什么时候做了什么？
2. tool_calls 里模型给了你什么？没给你什么？
3. 如果工具执行报错，此刻模型知道吗？——它什么时候才会知道？

---

### 第 4 次 · 手写 Agent Loop——agent 的心脏

> **核心认知：所有 agent 框架的核心就是一个 while 循环，你要脱离框架手写一遍。**

- 代码放：`02_ToolUse/`
- 学前阅读（约 30 分钟）：[What Is the AI Agent Loop?](https://blogs.oracle.com/developers/what-is-the-ai-agent-loop-the-core-architecture-behind-autonomous-ai-systems)（理解 reason → act → observe 循环）

**学习目标**
- 把第 3 次的单次往返变成 while 循环：模型自主决定"继续调工具"还是"给出最终答案"
- 理解循环的终止条件（正常与异常路径）

**练习任务（80 分钟）**
- [ ] （60 分钟）while 循环 agent：calculator + get_current_time + 读写本地文件 3 个工具，一直跑到模型不再发起调用
- [ ] （10 分钟）加最大循环次数上限（如 10 次），故意问一个无解的问题，观察护栏触发
- [ ] （10 分钟）每步打印过程日志：第几步、调了什么工具、什么参数

**复盘问题**
1. 循环的终止条件有哪几种正常/异常路径？
2. 不看代码，向想象中的同事白板讲解 agent loop 全流程
3. LangGraph 这类框架的核心循环，和你手写的有本质区别吗？

---

### 第 5 次 · 工具设计与错误处理——agent 质量的真正来源

> **核心认知：工具描述是写给模型看的，不是写给程序员看的。**

- 代码放：`02_ToolUse/`
- 学前阅读（约 30 分钟）：[Anthropic: Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) 的附录（工具设计 / ACI 最佳实践）

**学习目标**
- 掌握工具 schema 设计原则：像给聪明的实习生写文档一样写工具描述
- 工具报错时把错误信息回传给模型，让它自己纠正重试——而不是程序崩溃
- 学会裁剪工具返回值，防止 token 爆炸

**练习任务（80 分钟）**
- [ ] （50 分钟）天气助手（mock 数据即可）：先写一版"照抄 API 文档式"的工具描述，用 10 个问题记录调用准确率；再把描述改写成"给模型看的"，对比准确率
- [ ] （30 分钟）故意让工具抛错（城市不存在），把错误信息回传，观察模型如何自纠

**复盘问题**
1. 两版工具描述的准确率差多少？差在哪些具体措辞上？
2. "回传错误给模型"比"程序崩溃/吞掉错误"好在哪里？
3. 你最长的工具返回值是什么？裁剪/截断的判断标准是什么？

---

### 第 6 次 · 综合实战——个人笔记助手

> **核心认知：从 demo 到"自己真的会用"，中间隔着一堆边界情况。**

- 代码放：`02_ToolUse/`
- 学前阅读：无新材料——把前 5 次自己写的代码重读一遍，这本身就是最好的复习

**学习目标**
- 把前 5 次的能力组装成一个自己真的会用的 agent：多轮对话 + 文件读写工具 + 结构化存取
- 体验并记录"演示能跑"和"日常可用"的差距

**练习任务（80 分钟）**
- [ ] （60 分钟）完整笔记助手：`create_note` / `search_notes` / `append_note` 三个工具 + 本地 Markdown 存储
- [ ] （20 分钟）真实使用 15 分钟，把 3 个失败或不满意的案例记下来

**复盘问题**
1. 你记录的 3 个失败案例，根因分别在哪一层：prompt、工具设计、还是模型能力？
2. 这个 agent 和第 1 次的聊天机器人，本质区别是什么？

### 第 7 次 · RAG——给 agent 外接知识

> **核心认知：RAG 效果好不好，八成取决于检索，而不是生成。**

- 代码放：`03_RAG/`（上课时创建）
- 学前阅读（约 30 分钟）：平台文档的 embedding 接口部分；让 AI 导师用 10 分钟给你讲清"文本 → 向量 → 余弦相似度"

**学习目标**
- 理解 embedding 与余弦相似度
- 跑通最小 pipeline：加载 → 切分 → embedding → 检索 → 拼 prompt → 生成
- 给模型"知识库里没有"的拒答出口——幻觉的常见来源就是不给逃生口

**练习任务（80 分钟）**
- [ ] （60 分钟）mini 知识库问答：拿 3–5 份自己的真实文档（笔记、产品资料），固定长度切分 + API embedding + **numpy 余弦相似度检索**（刻意不引向量库，保持极简）
- [ ] （20 分钟）测试：问 5 个库里有的 + 3 个库里没有的问题，观察拒答行为

**复盘问题**
1. 找一个"答案明明在库里却没检索到"的例子：问题出在切分还是相似度？
2. 不给拒答出口时，模型对"库里没有"的问题做了什么？
3. chunk 大小你定的多少？依据是什么？

### 第 8 次 · 护栏与评估——不失控、可对比

> **核心认知：没有评估集的 prompt 调优，等于蒙眼调参。**

- 代码放：`04_多步Agent/`（上课时创建）
- 学前阅读（约 30 分钟）：[Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

**学习目标**
- 给 agent 加三道闸：最大步数、token/费用预算、拒答出口
- 建立最小评估集：固定测试题 → 改动 → 跑分对比，代替"感觉不错"

**练习任务（80 分钟）**
- [ ] （30 分钟）给笔记助手加护栏：步数上限、单次会话 token 预算、超限礼貌退出
- [ ] （50 分钟）建 10 题回归测试集（含 2 题应拒答题），写个跑分脚本，记录基线分数

**复盘问题**
1. 构造一个能让无护栏 agent 死循环或烧钱的输入，描述它为什么会失控
2. 为什么说"没有评估集的 prompt 调优"等于蒙眼调参？
3. 你的 10 题测试集里，最难判对错的是哪一题？你是怎么判的？

### 第 9 次 · MCP——工具的开放标准

> **核心认知：MCP 把"每个 agent × 每个工具"的 N×M 问题，变成了 N+M。**

- 代码放：`04_多步Agent/`（上课时创建）
- 学前阅读（约 30 分钟）：[MCP 官方文档 Getting Started](https://modelcontextprotocol.io/docs/2026-07-28/getting-started/intro)

**学习目标**
- 理解 MCP 解决什么问题：工具一次封装，任何 agent 皆可复用
- 分清 host / client / server 三个角色
- 跑通官方 quickstart，写一个最简 MCP server

**练习任务（80 分钟）**
- [ ] （20 分钟）读官方文档概念部分，画出 host / client / server 关系图
- [ ] （60 分钟）按官方 [quickstart](https://modelcontextprotocol.io/docs/2026-07-28/develop/build-server) 用 Python SDK 写一个最简 server（比如把第 5 次的天气工具包上去），接入一个 MCP 客户端验证跑通

**复盘问题**
1. 用自己的话说：没有 MCP 和有 MCP，工具生态的区别是什么？
2. MCP server 提供的工具，和你第 4 次手写的本地工具，对模型来说有区别吗？区别在哪一层？

### 第 10 次 · 毕业实战——Mini Agent 从零到一

> **核心认知：能用 2 小时独立交付一个完整小 agent，比花 2 个月"学完"所有框架更有说服力。**

- 代码放：`05_毕业项目/`（上课时创建）
- 学前阅读（约 30 分钟）：重读 [Anthropic: Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) 全文——此时再读，体感和第一遍完全不同

**学习目标**
- 综合全部所学，2 小时内独立交付一个完整可用的 mini agent（**允许且鼓励复用**前 9 次自己写的代码）
- 能向别人讲清架构、能力边界和已知失败模式

**练习任务（80 分钟，二选一，先写 5 行需求再动手）**
- [ ] 「研究小助手」：给一个主题 → agent 自主检索本地知识库 → 汇总成一页报告
- [ ] 「日志分析师」：读本地日志文件 → 回答"今天有什么异常" → 输出结构化摘要

硬性要求（缺一不可）：
- [ ] 有护栏（步数上限 + 预算）
- [ ] 每步过程日志
- [ ] 10 题评估集跑分（记下分数）
- [ ] README：一页架构图 + 已知失败模式清单

**复盘问题**
1. 这 20 小时里最大的"啊哈时刻"是什么？哪个认知你现在最有信心？
2. 你的 mini agent 最脆弱的一环是什么？如果再给 20 小时，你会补什么？
   （这个问题的答案，就是你接下来在 [00_学习路线图.md](00_学习路线图.md) 里的前进方向）

## 20 小时之后

按长期路线图继续，衔接点：

- **等级 3（RAG 深入）**：你在第 7 次课留下的切分/检索问题，这里全部展开（Chroma/pgvector、混合检索、20 题量化测试）
- **等级 4（多步 Agent）**：带着你手写过的循环去学 LangGraph / Agents SDK，一两天就能上手——因为你看得穿它每一步在做什么；长期记忆、人工介入也在这级
- **等级 5（完整交付）**：把 mini agent 升级成真产品（界面、tracing、安全、部署）

一个判断标准送给你：**能分清一个需求该用固定流程（workflow）还是自主决策（agent），是架构判断力的分水岭。** 20 小时后你应该已经站在这道线上了。
